# Golden Standard Studio — Pilot, Stage 4E review, and immutable Gold release

This directory contains the fixed ten-real-article Pilot plus the forty-article
Stage 4E expansion cohort. It reads upstream SQLite databases in read-only mode and
stores drafts in its own local `data/review.db`. It does not record human review timing.

```powershell
uv run uvicorn gold_standard_studio.app:app --host 127.0.0.1 --port 8765
```

Open <http://127.0.0.1:8765/queue>. Terra Provider and Sol Reviewer artifacts are
generated by Codex Subagents and imported from `data/candidates`; the web app never
calls a model or writes an upstream database. Reproducible rendered prompt packs are
stored under `data/runs/<article-id>`.

The review page separates S01B article-backed facts from deterministic normalization:
`entities`/`location` retain raw extracted facts, while `normalized_entities` and
`normalized_location` review S02B company-parent and location mappings independently.
The immutable article title and body are both valid verbatim evidence sources; the
page highlights whichever source contains the selected quote.
The maintained human annotation contract is
`../../docs/rules_and_plans/golden_standard_annotation.md`.

## Publish the Pilot Gold

Publication is local, read-only with respect to all upstream databases, and refuses
unconfirmed or schema-stale reviews. Check readiness first:

```powershell
uv run python -m gold_standard_studio.pilot_release check
```

After all ten records are ready, publish the immutable version once:

```powershell
uv run python -m gold_standard_studio.pilot_release publish --version pilot-v0.1.1
```

The version directory contains the evidence-preserving rich Gold, S01B/S02A/S02B/
end-to-end projections, an existing-eval-compatible S01B JSONL, a manifest with
artifact hashes, and a baseline labelled `stored_pipeline_snapshot`. That baseline
uses stored Pipeline/database results and does not call a model. Existing version
directories are never overwritten.

## Run a typed layered evaluation

Evaluate the immutable Gold release against the already stored Pipeline/database
snapshot without calling a model:

```powershell
uv run python -m gold_standard_studio.layered_evaluator --release-version pilot-v0.1.0 --run-id stored-snapshot-v2
```

The command writes an immutable run under
`data/evaluations/<release-version>/<run-id>/` and refuses to overwrite it. Its
report uses type-aware field comparisons, one-to-one project alignment, and records
unsupported or unavailable values as unscorable instead of counting them as model
errors. The current adapter supports the article-validity gate, S01B extraction
facts, S02B normalized entities/location, and the stored end-to-end projection.
Full cross-article S02A duplicate clustering and S03 province inference are not
available in this stored snapshot and are labelled unsupported explicitly.

## Compare the frozen Terra and Sol candidates

Run the development-set experiment over the ten candidates generated before Gold
publication by the Terra Provider and Sol Reviewer subagents:

```powershell
uv run python -m gold_standard_studio.frozen_candidate_experiment --release-version pilot-v0.1.1 --experiment-id frozen-terra-sol-v1
```

The immutable experiment is written under
`data/experiments/<release-version>/<experiment-id>/`. It validates model identity,
article hashes, Reviewer parent links, candidate completeness, and available rendered
Prompt provenance before scoring. The report compares only attributable S01B facts;
taxonomy, S02A, S02B, and S03 are excluded. These ten articles are a development set
because their candidates were visible during human Gold review, so use the result for
diagnosis rather than a leakage-free model ranking.

`pilot-v0.1.0` remains the original immutable Pilot. `pilot-v0.1.1` applies the
approved rules for acquisition versus development/financing, project-specific entity
roles, candidate locations, and construction participation. Its audit trail and
pre-change review database backup are under
`data/audits/pilot-v0.1.1-guideline-audit/`.

## Build or verify the Stage 4E cohort

The Master Plan targets 200 articles eventually, but Stage 4E adds only 40 new
articles: 24 development and 16 challenge, with no blind holdout. The original ten
Pilot articles remain development-only and are excluded from this cohort.

```powershell
uv run python -m gold_standard_studio.stage4e_manifest build --output-root data/cohorts
uv run python -m gold_standard_studio.stage4e_manifest verify data/cohorts/stage-4e-40-v1
```

The immutable directory contains `articles.jsonl` and `manifest.json`, including
article body hashes, split/stratum/family metadata, source database hashes, and
artifact provenance. Historical projects, categories, canonical IDs, and locations
are selection signals only, never Gold. The queue now groups Pilot development,
Stage 4E development, and Stage 4E challenge. Both splits show frozen Terra Provider
and Sol Reviewer candidates as human-review aids; challenge denotes future regression
use, not candidate hiding. Database history remains non-Gold, and unextracted boundary
samples are never auto-labelled as negatives.
