# Golden Standard 标注规则

> 当前版本：2026-08-12。本文是 Golden Standard 人工确认、冲突审计和后续 eval 的长期口径；模型候选、数据库旧值或 Reviewer note 均不能覆盖本文规则。

## 基本原则

- 标注目标是文章能够支持的正确答案，而不是选择与某个模型最接近的答案。
- 项目级字段必须由该项目的原文证据支持；公司、国家、区域或项目组合层面的概括不能默认下放到每一个项目。
- 草稿允许不完整；发布 Gold 前，每个字段必须完成确认或修改，并通过证据与结构校验。
- 事实抽取、确定性 taxonomy、实体归一化和地点归一化分层标注，不把后续规则结果倒灌为原文事实。

## 字段状态与原文证据

- 只有 `value_state=present` 的事实层字段要求可在固定新闻标题或正文中逐字定位的 evidence；标题与正文是并列的一手原文证据来源。
- `not_mentioned` 表示正文未提及，值与 evidence 都可以为空；不得为了通过确认而编造“未提及”的原文证据。
- `not_applicable` 与 `uncertain` 同样不强制原文证据；如正文有助于解释不适用或不确定，可以自愿保存证据或说明。
- `needs_adjudication` 允许保存草稿但不能进入正式 Gold release，必须先完成人工裁定。

## 项目开发商与股权收购

- 收购项目股权的企业不自动成为 `project_developer`。
- 只有原文明确称某实体为开发商，或明确描述其承担项目开发职责时，才标注为开发商。
- 原文明示另一个开发商时，应标注该实体；没有明确开发证据时标为 `not_mentioned`。
- 股权收购可以支持参与实体的“股权投资方/收购方”角色，但不能单独支持“项目开发商”。

## 实体参与角色

- 每个项目的实体角色必须由该项目的参建、EPC、设计、施工、设备供应、运维、投资等具体证据支持。
- 同一新闻或同一项目明确涉及多个中国企业时，应全部加入该项目的 `entities` 列表；每家企业独立保存原文名称、项目级角色和各自证据，不能只保留第一家，也不能把一家公司的角色复制给其他公司。
- 公司或区域层面的“一体化能力”“全产业链优势”“领先承包商”等概括，原则上不能自动复制为文章中每个项目的角色。
- 原文能确认实体与项目有关、但不能确认具体角色时，保留实体名称并将角色留空；不要为了字段完整而猜测角色。
- “参建”可以支持建设参与类角色；若原文进一步明确 EPC、设计、施工或设备范围，应采用更具体的角色。

## 项目名称与候选地点

- 候选地点、首选地点或仍在比选的场址不得写入项目名称，避免将未决信息固化为项目身份。
- `location` 只标注文章可确认的地点层级。具体场址未确定时，可以保留国家、地区或行政区等更高层级的确定地点。
- 候选场址可以保留在证据或审计说明中，但不能作为确定地点值。

## 融资模式

- 股权收购、股权转让、PPA 或 CfD 本身不等于项目融资模式。
- `financing_mode` 必须有融资行为或融资结构的明确证据，例如贷款、项目融资、股权融资安排、出口信贷或银团融资。
- 文章只描述项目所有权交易而未说明融资时，融资模式标为 `not_mentioned`。

## 项目阶段

- “参与建设/参建”足以支持 `project_stage=在建`，除非上下文明确表明项目尚未开工。
- 如果同一项目另有已完工、并网、投运等更晚阶段证据，应采用时间上更晚且更明确的阶段。

## 变更与版本

- 已发布 Gold 不得原地覆盖。任何事实或口径修订都发布新版本，并保留旧版本用于比较。
- 口径修订必须记录受影响文章、项目、字段、旧值、新值、证据和规则依据。
- Prompt、模型或 policy 实验不得在同一 run 中同时修改 Gold；Gold 变化和模型变化必须分别版本化。
