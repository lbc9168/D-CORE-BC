# 阶段三：数据库整理与导出（s03_data_exporter）

> 最后更新：2026-08-14（v2.1 四标签导出与 TX/MF 专用规格回归）

**子项目路径：** `s03_data_exporter/`

---

## 职责

把 s02a 主库的三表结构整理成"每项目一行"的扁平表与聚合统计，导出前端消费的静态 JSON/CSV，并自动同步到 s04。

---

## 当前功能

2026-08-14 已按迁移后主库离线重建：`projects_flat=3541`、`tx_flat=440`、`mf_flat=162`、`events_export=3541`。技术标签只输出受控四值及英文映射；confirmed-only 储能容量与发电 MW/TX/MF 专用规格继续严格分列。

### 七步导出流程

1. **省份提取**（`province_extractor.py`）：Gemini 从 `location` 提取一级行政区英文名，缓存至 `data/province_cache.json`。约束（`admin1_lookup.py`）：从 Natural Earth 已知省份列表（随 prompt 传入）中选择，输出必须来自列表或 null，防幻觉。
2. **扁平表构建**（`flat_builder.py`）：三表（canonical_projects/project_events/chinese_entities）合并为 `projects_flat`（每项目一行）；`excluded=1` 项目过滤掉；容量解析复用根 `bri_parse`。
3. **TX/MF 专用扁平表**（`flat_builder.py` 的 `build_tx_flat`/`build_mf_flat`）：为输变电建设（TX）/新能源制造业（MF）各建一张专用扁平表（`tx_flat`/`mf_flat`），仅未排除项目各一行；不含 `capacity_mw`/`storage_*`；当前前端未消费（TX/MF 仍 hidden，展示 tab 待排期）。
4. **聚合统计**（`stats_builder.py`）：构建 3 张预聚合表供前端直接查询。
5. **表格导出**：`projects_flat.xlsx` / `projects_flat.csv`（离线分析）。
6. **JSON 导出**（`json_exporter.py`）：输出静态 JSON，自动同步到 `s04/public/data/`（无需手动复制）。

另：事件级 CSV（`events_exporter.py`）单独导出 `events_export.csv`。

### projects_flat 核心字段（节选）

| 字段 | 说明 |
|------|------|
| `project_id / project_name(_en)` | 项目标识与中英文名 |
| `display_order` | 按项目最早事件日期升序的展示序号（老项目=1，无日期排末尾）；每次导出重算，前端默认排序键 |
| `stage_events` | JSON `[{group, year}]`，仅含 4 大类可见里程碑（pre_construction/under_construction/completed/acquired），升序；供前端区间过滤与趋势图 |
| `first_event_year / last_event_year` | stage_events 中最早/最晚年份 |
| `country(_en/_iso) / bri_country / ldc / province` | 国家与省级信息 |
| `category / category_en` | 能源类型中英文 |
| `subcategory / subcategory_en` | 项目子类（光伏：集中式/分布式；综合能源：光储/其他；其余类别空串）。DB NULL 在此渲染父类默认（光伏→集中式、综合能源→其他） |
| `capacity_mw` | 终态事件装机容量（储能/输变电/制造业类强制 null） |
| `pv_capacity_mw` | 综合能源项目光伏子项装机（终态优先第一个非空事件；其余类别 null） |
| `storage_power_mw / storage_energy_mwh / capacity_source` | 储能功率/能量与容量来源。**储能(ES)类保留这三列**（独立选值：capacity_mw 全空的纯储能项目也按终态优先取第一个 storage 非空事件）；TX/MF 仍全清 |
| `total_investment_usd / contract_amount_usd / financing_amount_usd` | 三类金额（百万美元），同规则：终态代表事件值，缺则最新有值事件。合同额/融资额仅新数据，历史 null |
| `latest_stage(_en/_date) / event_year` | 最终里程碑信息 |
| `financing_model(_en) / timeline_notes` | 融资模式 / 多事件时间线文字 |
| `primary_entity(_en) / all_entities / has_soe` | 主要中方实体 / 全部实体 JSON / 是否有央企 |
| `verification_status` | 来自 s02c 的验证状态 |

> 类别中英、阶段优先级与中英、融资模式、参与方式、`no_capacity` 标记均取自根 `enums_mapping.json`（经 `bri_enums`），改枚举只改 JSON 一处。

### tx_flat / mf_flat 专用扁平表

各一行 = 一个**未排除**的 TX（输变电建设）/ MF（新能源制造业）canonical 项目。基础列同 `projects_flat` 的一个子集：`project_id / project_name(_en) / country(_en/_iso) / province / latest_stage(_en) / event_year / all_entities`（JSON，形式与 `projects_flat.all_entities` 一致）。**无 capacity_mw、无 storage_* 列**。

| 表 | 专用列 | 取值规则 |
|------|------|------|
| `tx_flat` | `voltage_kv / line_length_km / transmission_capacity_mw` | 三列各自独立：按终态事件优先序取该列第一个非空值（互不要求同源事件） |
| `mf_flat` | `production_capacity_value / production_capacity_unit` | 两列强制同源：按终态事件优先序找第一个 `production_capacity_value` 非空的事件，value 与 unit 同时取自该事件（禁止跨事件配对） |

### 聚合统计表（3 张）

| 表名 | 维度 | 用途 |
|------|------|------|
| `stats_country` | country_iso × category × year | 地图热力图 |
| `stats_entity` | primary_entity × category × year | 企业排名图表 |
| `stats_timeline` | year × category × latest_stage | 终态分布（前端趋势图改用 stage_events，此表保留） |

### 事件级 CSV（`events_export.csv`）

`events_exporter.py` 按 **事件×中方公司** 拆条（1 事件 N 公司 → N 行；0 公司 → 1 行实体列留空），UTF-8 BOM，**39 列**（含 TX/MF 项目，单文件全量下载）：
`canonical_id, event_id, project_name_en/cn, country_en/iso, province, category_en/cn, subcategory_cn/en, stage_cn/en, stage_group_cn/en, year, month, capacity_mw, pv_capacity_mw, storage_power_mw, storage_energy_mwh, voltage_kv, line_length_km, transmission_capacity_mw, production_capacity_value, production_capacity_unit, total_investment_usd, contract_amount_usd, financing_amount_usd, financing_model_en, developer_cn/en, entity_cn/en, subsidiary_cn/en, involvement_type_cn/en, is_central_soe`。
子类列为项目级值每行重复（与 projects_flat 同口径渲染默认）；pv/storage/金额/TX/MF 规格列取事件自身值（无值空串）。**行序**：主表（发电+储能）→ 输变电 → 制造业，组内 canonical_id+event_id 升序——仅为人眼浏览优化，程序分析勿依赖。

基线双轨：主表类别走 `passes_baseline()`（复刻前端 `shouldExcludeByPolicy`：排除 CHN/HKG/MAC/TWN、最后事件年<2022、excluded/hidden 类别、unknown 主体、无容量的容量类别）；**TX/MF 走 `passes_txmf_baseline()`**（对齐前端 txmf 域：仅排中港澳台 + 终态事件年<2022，判定源为同库 `tx_flat/mf_flat.event_year`，⚠️不能用 projects_flat 的 last_event_year——后者只统计可见 viz 阶段会漏项目）。事件行统一限 `year>=2022`，使下载口径 = 网页口径。

### 数据字典（`data_dictionary.xlsx`）

由 `scripts/build_data_dictionary.py` 生成（`uv run --no-sync python s03_data_exporter/scripts/build_data_dictionary.py`），3 sheet：**READ ME**（给人和 AI 的使用信号：粒度去重食谱/容量语义/列适用矩阵/通用约定，动态嵌入行数与数据日期）+ **Columns**（39 列全字典含 Applies to）+ **Enums**（类别/阶段映射/子类/制造业单位，从根 enums_mapping.json 生成）。脚本启动时校验列集合与 `events_exporter._COLUMNS` 同步，漏列报错退出——**加列时改两处：exporter 列表 + 本脚本 `_COLUMNS` 文档表，然后重跑生成**。

> 阶段优先级（"最终状态"判定）：投入运营 > 竣工 > 在建 > 开工 > 签约 > 中标 > 收购。

## 如何运行

```bash
cd s03_data_exporter
uv sync
uv run run_export
```

## 输入 / 输出

- **输入**：`../s02a_duplicate_merger/data/db/bri_re_database.db`。
- **输出**（`data/output/`，JSON/CSV 自动同步到 `s04/public/data/`）：
  - `bri_re_export.db`（主 SQLite，含 `tx_flat`/`mf_flat` 表）
  - `projects_flat.xlsx` / `projects_flat.csv`
  - `projects_flat.json` + `tx_flat.json` + `mf_flat.json` + 3 张 stats JSON（country/entity/timeline）
  - `events_export.csv`（事件级拆条，UTF-8 BOM）
  - `metadata.json`（`last_updated` = project_events 最大 publish_date，`project_count`）

## 关键依赖与约束

- 依赖 google-genai（省份提取）+ pandas + openpyxl。
- `main.py` 顶部已做 UTF-8 stdout reconfigure（避免 detached GBK 控制台 `print` 触发 `UnicodeEncodeError`）。
- 重新生成需手动 `uv run run_export`（流水线中为预留步骤，默认不自动跑）。
