## 已实现功能

### 五步导出流程

**1. 省份提取**（`province_extractor.py`）
Gemini 从 `location` 字段提取一级行政区英文名，结果缓存至 `data/province_cache.json`，空值直接跳过。

**Natural Earth 约束**（`admin1_lookup.py`）：从 `s04/scripts/_ne_admin1_cache.zip` 加载各国已知省份列表（`{ISO3: [name_en, ...]}`），随 Prompt 传入 Gemini，输出必须来自列表或 null，防止幻觉；zip 不存在时退化为无约束行为。

**2. 扁平表构建**（`flat_builder.py`）
将 s02a 三表结构（canonical_projects / project_events / chinese_entities）合并为每项目一行的 `projects_flat` 表。
- **v2 S2a**：容量解析复用根 `bri_parse.parse_number`（`capacity_mw` 现为 REAL）；`canonical_projects.excluded=1` 的项目过滤掉（`.get` 兼容旧库）；新增储能/`capacity_source` 透传；投资额改取代表值。

**3. 聚合统计**（`stats_builder.py`）
构建 3 张预聚合表，供可视化前端直接查询。

**4. 表格导出**
输出 `projects_flat.xlsx` 和 `projects_flat.csv` 供离线分析。

**5. JSON 导出**（`json_exporter.py`）
输出 4 个静态 JSON 文件，自动同步到 `s04/public/data/`（无需手动复制）。

**6. 企业层级补充数据**（`supporting_docs/company_hierarchy.json`）
基于 `supporting_docs/` 内公司资料，整理母子公司层级（含部分三级公司）、中英文名称与央企标记，供后续公司维度分析与映射使用。

## projects_flat 核心字段

| 字段 | 说明 |
|------|------|
| `project_id / project_name / project_name_en` | 项目标识与中英文名 |
| `country / country_en / country_iso / bri_country / ldc` | 国家信息（country_en = 英文名，由 WorldCountryList.json 通过 ISO3 查表填充） |
| `province` | AI提取的省级行政区英文名（可为null） |
| `category / category_en` | 能源类型（中文 + 英文，如 "光伏" / "Solar PV"） |
| `capacity_mw` | 最终状态事件的装机容量（储能/输变电建设/新能源制造业类别强制为 null） |
| `storage_power_mw / storage_energy_mwh / capacity_source` | **v2 S2a**：储能功率/容量与容量来源，取自容量代表事件（多数项目为空） |
| `total_investment_usd` | **v2 S2a**：改为终态代表事件的投资额（空则最新有值事件），**不再取全事件均值**；百万美元 |
| `latest_stage / latest_stage_en / latest_stage_date / event_year` | 最终里程碑信息（含英文阶段名） |
| `financing_model / financing_model_en` | 融资模式（中文 + 英文） |
| `timeline_notes` | 多事件时的阶段时间线文字摘要 |
| `primary_entity / _en` | 主要中方实体（中英文） |
| `all_entities` | 全部实体 JSON 数组，每条含 `name/name_en/involvement_type/involvement_type_en/is_central_soe` |
| `has_soe` | 整数（0/1），该项目是否有央企参与 |
| `verification_status` | 来自 s02b 的交叉验证状态 |
