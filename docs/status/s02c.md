# 阶段二C：外部交叉验证（s02c_cross_verification）

> 最后更新：2026-10-06

**子项目路径：** `s02c_cross_verification/`

> 可选步骤：去重合并后可直接进入数据库整理，也可先做交叉验证再整理。

---

## 职责

用外部信源（GDELT 国际新闻）交叉验证主库中的项目事件，写回验证状态，低置信度记录导出人工核查清单。

---

## 当前功能

### CrossVerificationTool（四阶段）

1. **GDELT 批量查询**：按国家×能源类型从 GDELT 拉取标题（本地缓存，零 token）。
2. **多语言向量匹配**：Gemini Embedding 2（`gemini-embedding-2`）嵌入，项目与文章均用 `task: sentence similarity | query:` 前缀后按余弦相似度筛候选（当前默认阈值 0.65，尚未针对新模型重新校准）。文章向量缓存在带模型签名的 `article_embeddings_gemini-embedding-2.json`；旧 `text-embedding-004` 向量不复用，首次运行时需重新生成。
3. **LLM 确认**：逐对判断文章是否报道该项目（high/medium/low 置信度）。
4. **写回 + 导出**：更新验证字段；低置信度记录输出 Excel 人工核查清单。

---

## 当前限制

⚠️ **GDELT 查询找不到与主库匹配的信源**（至少近期数据找不到），交叉验证当前实际不可用，需另寻其他信源后再启用。这也是本模块标记"受限"的原因。

## 如何运行

```bash
cd s02c_cross_verification
uv sync
uv run s02c_cross_verification   # 入口 main.run()，直调 tool（纯 Python，无 crewAI）
```

---

## 输入 / 输出

- **输入**：`../s02a_duplicate_merger/data/db/bri_re_database.db`（读 `verification_status='unverified'`）。
- **输出**：更新同一 SQLite 的验证字段；低置信度记录 → `data/manual_review/` 下 Excel。
