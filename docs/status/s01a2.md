# s01a2_multi_crawler 状态

## 职责（一句话）

对多个中文信源站点做定时增量爬取（列表发现新 URL → 抓文章页 → 入本地库），并产出健康监控报告；v3 多源化试点，与 s01a（goalfore 爬虫）平级、在 s01b 之前。当前 9 站：Tier-1 六站（yidaiyilu/powerchina/powerchina_intl/seetao/imsilkroad/solarbe）+ Tier-2 三站（sasac/cpnn/nengyuanjie）。

## 当前功能

- 三种发现器：`html_list`（服务端渲染列表，电建国际/见道/新华丝路/索比）、`jpaas`（大汉 JPaaS CMS，运行时从壳页自取 API 参数，电建集团）、`sitemap_daily`（按日 sitemap，一带一路网）。
- 文章页统一提取：标题（og:title/h1/`<title>`，可按站覆盖来源并剥离站名后缀）、日期（HTML 正则 + URL 兜底）、正文（按站选择器 + 最大文本块兜底）。
- 增量与幂等：URL 为主键，已见即跳过；`--baseline` 首跑只登记水位线不抓文章（不回爬历史）。
- 礼貌与容错：curl_cffi Chrome 指纹、同站间隔 ≥3s、404 跳过 / 429 等 30s / 403 停站 / 5xx 指数退避、单站单轮 300 篇熔断、站间隔离。
- 健康报告：每次运行生成 `data/reports/health_report_{date}.md`（每站新增/错误/空列表页/距上次新增天数），有告警时退出码非 0。

## 如何运行

```bash
cd s01a2_multi_crawler
uv sync --extra dev
uv run crawl                 # 全部 6 站增量
uv run crawl --site seetao   # 单站
uv run crawl --baseline      # 首跑建水位线（新环境部署时执行一次）
uv run crawl --dry-run       # 只发现不写库
uv run health-report         # 单独重生成健康报告
uv run pytest tests/ -q      # 17 个测试
```

定时：Windows 任务计划每周触发 `uv run crawl`（未来迁服务器用 cron，同一命令）。

## 输入 / 输出

- 输入:`config/sites/*.yaml`（9 份站点适配器配置，含 `tier` 字段区分批次；Tier-1 六站 + Tier-2 三站 sasac/cpnn/nengyuanjie）。
- 输出:`data/crawl_state.db`——`articles`（url 主键、title、publish_date、content_text、status: baseline/fetched/error）、`fetch_log`（每站每轮运行统计）；`data/reports/health_report_*.md`；`data/logs/crawl_*.log`（UTF-8）。
- 暂不接下游：试点期不喂 s01b，攒 1 个月数据后做重叠率评估再设计整合。

## 关键依赖与约束

- 依赖：curl_cffi（Chrome TLS 指纹，电建 JPaaS API 的必要条件）、beautifulsoup4、pydantic、pyyaml。
- 原文正文只存本地供后续提取，不对外发布（版权约束）；goalfore 链接不作对外 source_link 的约束在下游继续有效。
- 站点改版信号：列表页 0 命中会进健康报告告警；JPaaS 参数运行时自取可容忍参数级改版。
- 已知噪音：imsilkroad 标签页偶混入非文章链接（如数据库宣传页），抓到 0 字正文，已被水位线记住不复抓。
