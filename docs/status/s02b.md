## 已实现功能

### entity_normalizer（实体名称归一化工具）

五步流程：

**0. Unknown 变体统一**
将 `未知`、`不详`、`不明`、`暂无`、`N/A` 等变体统一替换为 `Unknown`。

**1. 加载实体名**
从 `chinese_entities` 表读取所有不重复的 `implementing_entity` 及出现频次。

**2. 三信号候选筛查**
- Signal 1: `token_sort_ratio ≥ 80`（词序无关相似度）
- Signal 2: `partial_ratio ≥ 90` + 长度比约束（覆盖"子公司简称"情况）
- Signal 3: 子序列缩写检测（捕获"中国电建 ↔ 中国电力建设集团"类）

**3. LLM 批量确认**
Gemini 批量判断候选对是否为同一公司，并选定规范名称（batch_size=25）。

**4. Union-Find 构建映射**
将所有已确认的同一公司集合合并，生成 `{别名 → 规范名}` 映射。

**5. 写入数据库**
更新 `chinese_entities` 表的 `implementing_entity` 和 `subsidiary_name` 两列。

## 数据接口

- **输入**：`../s02a_duplicate_merger/data/db/bri_re_database.db`（`chinese_entities` 表）
- **输出**：原地更新同一 SQLite 的 `implementing_entity` / `subsidiary_name` 字段

## 运行方式

```bash
cd s02b_entity_normalizer
uv sync                          # 首次安装
uv run normalize_entities        # 正式运行，写入数据库
uv run normalize_entities --preview   # 仅预览候选对，不写入
uv run normalize_entities --db /path/to/custom.db  # 指定数据库路径
```

## 与 s01b 的分工

| 场景 | 处理方 |
|------|--------|
| 实体在 `company_hierarchy.json` 中有对应条目 | s01b 提取时已直接写入规范名 |
| 实体不在对照表中（如小型民企、外资） | s02b 通过模糊匹配 + LLM 归一 |
| 历史已入库数据的名称修正 | s02b |
| `subsidiary_name` 字段的未匹配变体 | s02b |
