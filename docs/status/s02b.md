## 已实现功能

### entity_normalizer（实体名称归一化工具）

五步流程：

**0. Unknown 变体统一**
将 `未知`、`不详`、`不明`、`暂无`、`N/A` 等变体统一替换为 `Unknown`。

**1. 加载实体名**
从 `chinese_entities` 表读取所有不重复的 `implementing_entity` 及出现频次。

**2. 三信号候选筛查**
- Signal 1: `token_sort_ratio ≥ 80`（词序无关相似度）
- Signal 2: `partial_ratio ≥ 90` + 长度比约束（覆盖"子公司简称"情况）
- Signal 3: 子序列缩写检测（捕获"中国电建 ↔ 中国电力建设集团"类）

**3. LLM 批量确认**
Gemini 批量判断候选对是否为同一公司，并选定规范名称（batch_size=25）。

**4. Union-Find 构建映射**
将所有已确认的同一公司集合合并，生成 `{别名 → 规范名}` 映射。

**5. 写入数据库**
`_update_db(db_path, impl_mapping, sub_mapping=None)`：用 implementing 映射只归一 `implementing_entity` 列。
- **v2 S5d（2026-05-24）修复**：原实现把仅由 `implementing_entity` 构建的映射**同时套用到 `subsidiary_name`**，导致母公司别名误改子公司名（如某行 subsidiary 恰为"中国电建"会被错改）。现拆分为两个独立映射参数，subsidiary 仅在显式传入 `sub_mapping` 时才更新；当前 `run` 只传 impl_mapping（subsidiary 归一暂不做，留待 v2.1）。批量写改 `executemany`（CLAUDE.md 规则3）。
