# 阶段二B：实体名 + 地点归一化（s02b_entity_normalizer）

> 最后更新：2026-06-24

**子项目路径：** `s02b_entity_normalizer/`

---

## 职责

在 s02a 去重合并后、s02c 交叉验证前运行，统一主库中中方公司名变体（`implementing_entity`）与项目地点名（写 `location_norm`）。原地更新主库。

---

## 当前功能

### 实体名归一化（`entity_normalizer.py`）

五步流程：

0. **Unknown 变体统一**：`未知/不详/不明/暂无/N/A` 等统一为 `Unknown`。
1. **加载实体名**：从 `chinese_entities` 读全部不重复 `implementing_entity` 及频次。
2. **三信号候选筛查**：`token_sort_ratio≥80`（词序无关）/ `partial_ratio≥90` + 长度比约束（子公司简称）/ 子序列缩写检测（"中国电建 ↔ 中国电力建设集团"）。
3. **LLM 批量确认**：Gemini 判断候选对是否同一公司并选规范名（batch_size=25）。
4. **Union-Find 构建映射**：合并同一公司集合，生成 `{别名 → 规范名}`。
5. **写库**：`_update_db` 只归一 `implementing_entity` 列（`executemany` 批量写）。`subsidiary_name` 仅在显式传入 `sub_mapping` 时才更新，当前 `run` 不传（子公司归一留待后续），避免母公司别名误改子公司名。

### 地点归一化（`location_normalizer.py`）

- `normalize_locations` 写 `canonical_projects.location_norm`（**只增列、不动原 `location`**；下游 s03/s04 当前不消费 → 零功能影响、可逆）。
- 匹配规则在根 `bri_location.py`：多地名串排除、partial 长度比守卫、方向签名守卫（前缀/复合中部/后缀）、positional 收紧，防止 union-find 把共享岛名/后缀的不同省跨省级联误并。

## 如何运行

```bash
cd s02b_entity_normalizer
uv sync
uv run normalize_entities                # 实体名归一（写库）
uv run normalize_entities --preview      # 仅预览候选对，不写库
uv run normalize_entities --db /path/to/custom.db
```

## 输入 / 输出

- **输入**：`../s02a_duplicate_merger/data/db/bri_re_database.db`（`chinese_entities` + `canonical_projects`）。
- **输出**：原地更新同一 SQLite——`implementing_entity`（实体归一）、`location_norm`（地点归一，新增列）。

---

## 与 s01b 的分工

| 场景 | 处理方 |
|------|--------|
| 实体在 `company_hierarchy.json` 中有条目 | s01b 提取时已写规范名 |
| 实体不在对照表中（小型民企/外资） | s02b 模糊匹配 + LLM 归一 |
| 历史已入库数据的名称修正 | s02b |

---

## 关键依赖与约束

- 依赖 rapidfuzz + google-genai。`run()` 被 pipeline 以函数参数调用时不解析 `sys.argv`，仅纯 CLI 调用才读 `--db/--preview`。
- 地点归一的合并质量依赖 LLM：音译近似的不同省可能偶发误并。`location_norm` 当前不喂下游，属软信息；后续若让 s03/s04 消费需先人工抽查。
