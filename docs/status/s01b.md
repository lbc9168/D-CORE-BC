# 阶段一B：AI 提取筛选（s01b_project_extractor）

> 最后更新：2026-07-04（实体名质量专项）

**子项目路径：** `s01b_project_extractor/`

---

## 职责

从 s01a 的 `raw_news.db` 读取原始新闻，用 LLM 做**分阶段结构化提取**，经三层质量校验后写入 `projects.db`，供 s02a 去重合并。

---

## 当前功能

### 分阶段提取链（`stages/orchestrator.py: extract_staged`）

纯 Python orchestrator（无 crewAI），把单次提取拆成 5 个阶段串联：

```
S1 相关性 / 中企门槛 → S2 项目识别（防过度拆分）
  → 逐项目 S4 中方实体（母子公司归一）→ S3 金融 → S5 摘要 + 自检纠偏
```

`extract_one` 与生产写库路径 `_process_df` 均委派此 orchestrator，返回结构契约一致。

### 分阶段供应商路由（`llm/client.py: StageRouter`）

按阶段选 LLM provider，env `S01B_STAGE_PROVIDERS` 配置。**当前默认（写入 .env）= `s3:deepseek,s4:deepseek,s5:deepseek`**——即 S1/S2 用 Gemini（保项目覆盖率），S3/S4/S5 用 DeepSeek。不设该 env = 全 Gemini。三方对比见 `docs/rules_and_plans/eval.md`。

### 提取流程要点

- **Python 端预筛**：先用关键词（光伏/风电/MW 等）快速过滤，节省 API 调用。
- **增量去重**：每次运行前从 `projects.db` + `review.db` 预加载已处理 URL 跳过重复（并发安全：原子检查 + 占位）。
- **发布日期前向填充**：并发前按顺序预计算，URL 日期不可解析时沿用上一条有效发布日期。
- **批次内并发**：`ThreadPoolExecutor(max_workers=4)`，无逐文章 sleep。
- **重试**：AI 调用失败指数退避重试最多 3 次。
- **三路写入**：`valid_project` → `extracted_projects`；`no_chinese_participation` / `irrelevant` → `review.db`。
- **未具名中企（chinese_unnamed）**：项目信息正常入库，实体写占位（`未具名中企` / `is_unnamed_placeholder=1`），同时在 `review.db/review_queue` 写一条 `reason_type="unnamed_entity"` 待复核条目。
- **S2 中排除决策记录**：S2 `in_scope=false` 时写 `excluded=1, exclude_source='extraction'`（确保所有排除决策留有记录）。
- **S1 prompt 排除规则**（`prompts/s1_relevance.py`）：矿产/化肥/化工/冶金/建材产品本身不录入；制造业限新能源装备/材料；绿氢须明确可再生电来源种类，仅提「绿氢」无种类 → 排除。
- **S2 prompt 规则**（`prompts/s2_basic.py`）：综合能源(HB)每子项须有发电/储能 + MW/MWh 计量；绿氢按绿电来源种类分类（光伏→PV/风电→WD/水电→HY），来源未明确 → `in_scope=false, Category=Unknown`。

### 翻译入口行为（`tools/project_extractor_tool.py: _resolve_entity_en / _resolve_developer_en`）

- **ASCII 直通**：`_resolve_entity_en(cn)` 入口若输入已是纯 ASCII 字符串，直接返回原值——不查缓存、不调 LLM（英文原名保留原样，不经翻译改写）。
- **developer 拆串翻译**：`_resolve_developer_en` 将 `project_developer` 字段按 `DEV_SEP_RE`（`[;；、，,/]`）拆分，对每个部件分别调用 `_resolve_entity_en` 翻译，结果以 `'; '` 拼回；两处 developer 调用点均接入此逻辑。
- **缓存写入守卫**：多公司串（含分隔符）或超长键（>30 字）翻译后**不写缓存**，防止垃圾键积累。
- **已知取舍**：缓存中已有 ~30 个 value-added 英文键（如 `"Canadian Solar"→"Canadian Solar Inc."`）属 ASCII，被直通后其增量后缀（"Inc."/"Ltd."）不再追加——符合「缩写为主」口径，已知接受。

### 缓存审计 CLI（`tools/cache_hygiene.py`）

六规则扫描 `company_name_cache.json`：R1 键含分隔符（多公司串/头衔串）、R2 键含头衔职位词、R3 键为占位泛指短语、R4 键超长(>30字)、R5 值含中文、R6 值含换行/超长/括注噪声；`verified=true` 全部豁免。支持 `--corrections CSV` 通道（`cn,en,en_abbr,verified,source`）修改/新增键值。

### 实体标准化知识库（动态注入 prompt）

- `supporting_docs/company_hierarchy.json`：17 家顶级集团 + 三级层级，含 `is_central_soe` 标记（懒加载缓存）。
- `supporting_docs/soe.md`：官方央企名录，用于 hierarchy 未覆盖企业的央企兜底判断。
- `implementing_entity` 填顶级集团规范名；`subsidiary_name` 在对照表有对应则填层级规范名，否则填原文。

### Layer 0：确定性非能源兜底（`guardrails/nonenergy_check.py`）

写库前强制执行，不依赖 LLM：

- `check_nonenergy(name, summary, category, capacity_mw, capacity_details) -> str | None`：发电语义词白名单放行（发电/电站/光伏/风电/水电/储能/地热/太阳能/并网/装机/MW 等；核电无单独词条，但「核电站」命中「电站」亦被保护）+ 黑名单拦截（天然气/油田/LNG/矿业/化工/海水淡化等），返回排除理由字符串或 None。
- 容量吨/年守卫（`capacity_is_tonnage`）：容量字段以吨/年计时 `capacity_mw` 置 NULL，不做 ÷1000 启发式转换，原文保留于 `capacity_mw_raw`。
- 绿氢/电解守卫：名称或摘要含绿氢/电解词，若未同时提供「绿电来源种类（光伏/风电/水电等）+ 明确装机容量 (>0 MW)」→ 排除（用户规则 2026-07-02）。
- 命中时写 `excluded=1, exclude_source='deterministic_guard'`，项目仍落 `extracted_projects` 供追溯，对 s02a 不可见。
- **Layer 0 接入点**：确定性守卫在写库前调用，改写为 `excluded=1, exclude_source='deterministic_guard'`；项目仍落 `extracted_projects` 供追溯，但对 s02a 不可见。

### 三层 AI Guardrail（`guardrails/`）

| 层 | 文件 | 功能 |
|----|------|------|
| 1 | `format_checks.py` | JSON schema 合法性、必填字段、枚举范围校验 |
| 2 | `semantic_checks.py` | 独立模型交叉验证：基于 `project_summary` 反推关键字段，比对一致性（并发批处理） |
| 3 | `batch_checks.py` | 批次统计异常检测（有效率/剔除率偏差告警） |

> format + batch 校验由写库路径 `_process_df` 直接调用；semantic_checks 保留备用。Layer 0 在所有 AI guardrail 之前执行。

## 输出字段（projects.db → extracted_projects 表）

| 字段 | 说明 |
|------|------|
| record_type | 具体项目 / 设备订单 / 一般合作（AI 判断） |
| project_name / project_name_en | 中英文项目名 |
| country / country_iso / bri_country / ldc | 国家信息（WorldCountryList.json 补充） |
| category | 12 类规范集（光伏/风电/水电/核电/地热及余热/生物质/储能/综合能源/火电/新能源制造业/输变电建设 + Unknown） |
| capacity_mw_raw / capacity_mw / capacity_details | 装机容量：原文(TEXT) + 解析值(REAL) + 明细 |
| storage_power_mw / storage_energy_mwh / capacity_source | 储能功率/容量(REAL) + 容量来源(TEXT)；storage 当前多留空 |
| project_stage | 拟开发/收购/中标/签约/开工/在建/竣工/投入运营/Unknown |
| project_developer | 项目开发商（多个 `;` 分隔） |
| implementing_entity / _en | 中方实体母公司（中英文） |
| is_central_soe | 是否央企（1/0/NULL）。三级优先级：① hierarchy 对照表 → ② soe.md 兜底 → ③ false |
| subsidiary_name / _en | 子公司（中英文） |
| involvement_type | BOT/BOOT / EPC总承包 / 设计·施工服务方 / 股权投资方 / 设备供应商 / 投融资+EPC / 融资方 / Unknown |
| subcontract_amount_usd_raw / _usd | 分包金额：原文(TEXT) + 解析值(REAL，百万美元) |
| total_investment_usd_raw / _usd / investment_date | 总投资：原文 + 解析值 + 财务成交日 |
| planned_start_date / planned_complete_date | 开工/竣工日期 |
| financing_model / _details | 融资模式及详情 |
| source_link / publish_date | 原文链接 / 发布日期 |
| project_summary | 2–3 句事实摘要（供 semantic_checks 交叉验证） |
| is_unnamed_placeholder | 实体为占位"未具名中企"时为 1 |
| batch_id / imported_to_s02a | 来源批次 / 是否已被 s02a 导入（增量标志） |

> 数值字段统一 `*_raw(TEXT,原文)` + REAL（由根 `bri_parse.parse_number` 解析）；枚举取自根 `enums_mapping.json`（经 `bri_enums`）。

## 如何运行

```bash
uv --project s01b_project_extractor sync
uv --project s01b_project_extractor run run_bulk_extract   # 批量提取（= main.run，默认 4 并发）
```

### 非能源回溯清扫（历史数据治本）

```bash
cd s01b_project_extractor

# Dry-run：输出 CSV 报告，不修改数据库
uv run sweep_nonenergy --db data/projects.db --out /path/to/dryrun.csv

# Apply（GATED）：先备份 .bak.YYYYMMDD_HHMMSS，再批量 excluded=1
uv run sweep_nonenergy --db data/projects.db --apply
```

> `--apply` 执行前须用户复看 dry-run CSV，确认无误后再操作。Apply 后需重跑 s02a → s03 → 部署。

### 缓存审计（历史垃圾键清理）

```bash
cd s01b_project_extractor

# Dry-run：扫描 company_name_cache.json，输出清理候选报告
uv run cache_fix \
  --cache <路径>/supporting_docs/company_name_cache.json \
  --corrections <路径>/supporting_docs/cache_corrections/2026-07-04-hard-errors.csv \
  --out /path/to/report.csv

# Apply（GATED）：用户复看报告后执行
uv run cache_fix --cache ... --corrections ... --apply
```

种子 corrections 文件：`supporting_docs/cache_corrections/2026-07-04-hard-errors.csv`（4 条已知错译，`verified=false`，需核实后改为 `true` 再 apply）。

## 输入 / 输出

- **输入**：`s01a_news_crawler/data/raw_news.db`（默认路径，可参数覆盖）。
- **输出**：
  - `data/projects.db` — 有效项目（`extracted_projects`）+ 写库前自动 `.bak` 备份主库。
  - `data/review.db` — 无中方参与 / 被过滤记录 + `review_queue` 复核队列。
  - `data/All_AI_Results_*.json` — AI 原始结果备份。

## 关键依赖与约束

- LLM 统一经 `llm/client.py`（`LLMClient` / `config_from_env`），默认 gemini-2.5-flash-lite，可分阶段切 DeepSeek。
- 知识库 `knowledge/user_preference.txt` + `main_equipment.json` / `capacity_factors.json`；外部对照表 `supporting_docs/`。
- 提取质量有配套评测框架（`eval/`）与复核机制（`review/`），详见 `docs/rules_and_plans/eval.md`、`review.md`。
