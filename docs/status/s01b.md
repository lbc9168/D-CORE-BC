## 定位

`s01b_project_extractor` 是阶段一的第二步，从 `s01a_news_crawler` 输出的 `raw_news.db` 读取原始新闻，调用 Gemini AI 进行结构化提取，并经过三层质量校验后写入 SQLite 数据库，供 `s02a_duplicate_merger` 读取。

**数据流：**
```
s01a_news_crawler/data/raw_news.db
  → ProjectExtractorTool（Gemini AI）
    → 三层 Guardrail 校验
      → s01b_project_extractor/data/projects.db（有效项目）
      → s01b_project_extractor/data/review.db（无中方参与 + 被过滤）
```

## 已实现功能

### AI 提取（ProjectExtractorTool）
`tools/project_extractor_tool.py`

- **模型**：Gemini gemini-2.5-flash-lite（google.genai SDK）
- **输入**：从 `raw_news.db` 按 `batch_id` 或全量读取关键词匹配新闻
- **Python 端预筛**：先用关键词（光伏/风电/MW 等）快速过滤，节省 API 调用
- **增量去重**：每次运行前从 `projects.db` + `review.db` 预加载已处理 URL，跳过重复项（并发安全：原子性检查+占位）
- **发布日期前向填充**：并发前按顺序预计算，保证前向填充正确性
- **批次内并发**：`ThreadPoolExecutor(max_workers=4)`，同时发 4 个 AI 请求；无逐文章 sleep，大幅提升批量处理速度
- **重试机制**：AI 调用失败时指数退避重试最多 3 次
- **AI 分类输出**：`valid_project` / `no_chinese_participation` / `irrelevant` 三路写入

### 实体标准化知识库（动态注入）
（2026-03-21 更新，替换原硬编码知识库）

- **`supporting_docs/company_hierarchy.json`**（单一可信来源）：17 家顶级集团 + 三级层级（二级子公司、三级子公司），含 `is_central_soe` 标记；运行时读取，懒加载缓存
- **`supporting_docs/soe.md`**（央企兜底名录）：官方100家中央企业列表；用于 hierarchy 未覆盖企业的 `is_central_soe` 兜底判断
- **提取逻辑**：`_get_entity_lookup_text()` + `_get_soe_list_text()` 在 `_build_prompt()` 调用时注入 prompt
- **实体名规范化**：`implementing_entity` 填顶级集团规范名；`subsidiary_name` 在对照表中有对应条目时填层级规范名，找不到时填原文名称（2026-03-22 更新）

### 三层 Guardrail 校验
`guardrails/`

| 层级 | 文件 | 功能 |
|------|------|------|
| 1 | `format_checks.py` | JSON schema 合法性、必填字段、枚举值范围校验 |
| 2 | `semantic_checks.py` | 独立模型交叉验证——基于 `project_summary` 反推关键字段，比对提取结果是否一致；**并发批处理**（`batch_size=20`，`max_workers=4`），比原串行快 3-5x |
| 3 | `batch_checks.py` | 批次统计异常检测（有效率/剔除率偏差告警） |

> **Phase 5 起**：crewAI 回调胶水 `extraction_guardrail.py` 已删除；format + batch 校验改由写库路径 `_process_df` 直接调用（Task 5.2）。semantic_checks 保留备用。

## 2026-04-10 Guardrail batch_id side-channel 修复

- **问题**：`TaskOutput.raw` 是 LLM agent 的自然语言回答（非 tool 返回值），regex `batch_id=(\S+)` 永远匹配不到，导致：① 校验回退到 DB 最新批次（功能正常）；② 但删除保护阻止清理不合格记录；③ 重试时旧坏记录堆积。
- **修复**：在 `project_extractor_tool.py` 添加模块级 side-channel（`get_last_batch_id()` / `reset_last_batch_id()`），tool 写入 DB 后设置 `_last_batch_id`；`extraction_guardrail.py` 优先读 side-channel，移除 `batch_id_from_output` 删除保护，确保校验失败时能正确删除不合格记录再重试。

## 2026-04-19 involvement_type 语义纠偏 + 存量修复脚本

- **`semantic_checks.py`**：新增 `VALID_INVOLVEMENT_ENUMS`；将 `involvement_type` 纳入语义纠偏（Layer 2 现在检查 stage / category / involvement_type 三字段）
- **`extraction_guardrail.py`**：`_apply_semantic_fixes()` 的 `allowed` 白名单加入 `"involvement_type"`，使纠偏建议可自动写回 DB
- **新增 `repair_involvement_types.py`**：一次性存量修复脚本，调用 Gemini 将 `projects.db` 中非法 `involvement_type` 语义映射到合法枚举并 UPDATE，运行后需重跑 s02a → s03

## 2026-04-26 implementing_entity 空值兜底修复

- **问题复盘**：Layer 1 将 `implementing_entity` 作为必填；当提取结果留空时，Guardrail 会删除失败记录并重试，但重试仍可能产生同类空值，最终因重试耗尽失败。
- **提取侧兜底**：`project_extractor_tool.py` 新增 `_normalize_implementing_entity()`，将空值统一标准化为 `"Unknown"`；无 `chinese_entities` 时默认写入 `Implementing Chinese Entity="Unknown"` 与英文同值。
- **Prompt 约束补强**：在实体填写规则中新增硬约束：`Implementing Chinese Entity` 不能为空，无法判断时必须填 `"Unknown"`。
- **入库前二次保护**：写入 `projects.db` 前再次标准化 `Implementing Chinese Entity`，防止并发分支/异常路径写入空值。
- **Guardrail 可观测性增强**：`extraction_guardrail.py` 增加 `implementing_entity` 空值预警和 `Unknown` 占比日志，便于批次质量监控。

## 2026-04-10 语义纠偏机制最小改造

- **语义范围收敛**：`semantic_checks.py` 的 prompt 仅校验并建议纠偏 `project_stage` / `category`，移除 `implementing_entity`、`subsidiary_name` 等高歧义字段，降低误报。
- **输出受枚举约束**：要求校验模型只输出允许枚举中的 `suggested_value`，并返回 `confidence`；低置信建议（<0.8）忽略。
- **Guardrail 自动应用纠偏**：`extraction_guardrail.py` 新增 `_apply_semantic_fixes()`，对高置信纠偏建议写回 `projects.db`，再执行格式校验，减少“仅报错不纠偏”导致的重试放大。

## 2026-04-09 历史数据清洗

- **历史数据规范化**：新增 `scripts/clean_historical_data.py`，对 `projects.db` 中 `project_stage`、`involvement_type`、`category` 三字段的非规范历史值做规则映射，共清洗 1,890 条记录（stage: 179、involvement: 1,633、category: 78）。
- **`VALID_CATEGORIES` 补充 `Unknown`**：`format_checks.py` 的 `VALID_CATEGORIES` 新增 `"Unknown"`，与其他字段的允许值集合保持一致，避免无法归类的记录触发 Guardrail 格式错误。

## 2026-03-22 稳定性修复

- **Category 枚举一致性**：提取 prompt 中输变电类项目的取值已统一为 `输变电建设`（与 Layer 1 `VALID_CATEGORIES` 对齐，避免无效重试）。
- **Guardrail 防误删保护**：当 `TaskOutput` 未成功解析 `batch_id` 时，Guardrail 不再删除疑似失败记录，仅返回错误并触发重试，避免误删非本批次数据。
- **Guardrail 批次回退策略**：`batch_id` 缺失时仅回退到“最新有效 batch_id”进行校验，不再使用“最近100条记录”跨批次混检。
- **央企名录格式修复**：将 `supporting_docs/soe.md` 统一为两列 Markdown 表格（`序号 | 企业(集团)名称`），`_get_soe_list_text()` 按原解析逻辑即可正确加载并只打印一次加载信息。
- **SQLite 入库占位符修复**：`extracted_projects` 的 `INSERT` 语句已对齐为“37 列 = 36 个参数 + `imported_to_s02a=0` + `created_at`”，解决“36 values for 37 columns”导致的提取中断。
- **入库失败结果保全**：新增兜底机制，若写库异常会将本轮解析结果落盘为 `All_AI_Results_*_failed.json`（含 valid/no_chinese/discarded/all_ai_results），避免长批次结果丢失。
- **语义校验进度提示**：Layer 2 新增批次进度日志（`当前批次/总批次`、本批条数、累计错误数、单批耗时），便于长任务监控与故障定位。
- **语义校验缩进修复**：修复 `semantic_checks.py` 中进度日志重构引入的缩进/控制流错误（`Unexpected indentation`），并整理为可稳定运行的并发批次校验结构。
