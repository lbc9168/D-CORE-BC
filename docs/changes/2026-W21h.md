## 新增模块 `eval/`（仓库根）

- **`eval/metrics.py`**（Task 1，TDD）：评测比较器。`cmp_status`（精确）/ `cmp_enum`（经 `bri_enums` 归一后相等）/
  `cmp_numeric`（`bri_parse` 解析后相对误差 ±5%）/ `entity_prf`（集合 P/R/F1）；`score_record(pred, gold)` 汇总——
  **status 为闸门**，错则字段不计分，且仅 gold `status==valid` 才打字段分。
- **`eval/predict.py`**（Task 5）：`flat_prediction(result)` 把提取器原始 result 映射为评测用扁平记录
  （status + 主项目 common_info 字段 + 中方实体）。status 映射 `valid_project→valid` / `no_chinese_participation→no_chinese` /
  `irrelevant→irrelevant`；P0 多项目只取主项目。
- **`eval/article_store.py`**（Task 4，TDD）：`get_article(url, db_path)` 从 raw_news 库取原文；
  `cache_key/cache_get/cache_put` 按 `url+提取器版本` 缓存提取结果，避免重复付费调用 Gemini；
  `DEFAULT_RAW_NEWS / DEFAULT_CACHE_DIR` 经上溯仓库根定位（库在主仓库 s01a 下）。
- **`eval/build_draft.py`**（Task 3）：分层抽样器，按 category + 难度桶（容量缺失 / 数据中心 / 设备供应商 / 无关 / 负样本）
  抽 `source_link`，预填 `ai_<field>` 只读列、留空 `<field>` 人工修正列，写 utf-8-sig CSV（`eval/draft.csv`）；
  CLI 入口走 Pydantic 校验（n>0 / out 父目录存在 / projects-db 存在）。
- **`eval/gold_loader.py`**（Task 5）：`load(path)` 逐行读 `gold_set.jsonl`，Pydantic 校验每条
  `{source_link, article_id?, labels{扁平 schema}}`；任一行非法（如 status 不合法）**带行号立即抛 ValueError**（外部数据边界）。
- **`eval/run_eval.py`**（Task 5）：评测主程序。取原文→（缓存或）提取→扁平化→打分→聚合→写
  `eval/reports/<ts>.json`→打印各指标相对上次报告的 ↑/↓/= 对比。`weighted_total` 四分量（status/enum/numeric/entity）
  默认等权（`WEIGHTS`，可调），无数据分量丢弃后重新归一化。`run_eval(extract_fn=, extractor_version=)`
  双参注入时走纯本地路径（genai / s01b 提取器均为延迟导入，不触发 Gemini）。
- **`eval/README.md`**（Task 6，本次）：标注 + 评测全流程文档（build_draft → 人工标注 → gold_set.jsonl → run_eval），
  含主仓库 DB 路径的实跑命令、jsonl 期望形状、打分规则、git 忽略说明。
