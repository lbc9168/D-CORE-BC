## 背景 / 为什么

用户反馈：网页加载慢；Overview 趋势图想支持"具体年份看各能源类别 + Project Count/Capacity 切换"，且低饱和度类别色与其它图不搭；以及 milestone / project / event 三个概念在站内易混淆。逐项实现并在浏览器实测。

## 批次一：前端加载性能

- **路由级懒加载**：首页（Map）同步加载，其余 4 页 `React.lazy` + `Suspense`（[App.tsx](../../s04_web_visualization/src/App.tsx) / [Layout.tsx](../../s04_web_visualization/src/components/layout/Layout.tsx)，侧栏在 chunk 载入期间保持可见）。
- **vite `manualChunks`**：react / recharts / react-simple-maps 拆独立 chunk（[vite.config.ts](../../s04_web_visualization/vite.config.ts)）。
- **效果**：首屏 JS 从单块 736 KB（gzip 216 KB）→ 约 289 KB（gzip ~95 KB），recharts 110 KB gzip 推迟到访问 Overview 才载。
- **新增 spec**：[docs/superpowers/s04-server-deploy-performance.md](../superpowers/s04-server-deploy-performance.md)——部署到自有服务器时的服务器端加速设置（gzip 保底 + brotli 增量 + 缓存头 + HTTP/2/3 + CDN/国内节点 + 验证清单，含 nginx 示例）。说明：数据大头是 8.5MB 的 `projects_flat.json`，服务器端只能靠压缩降传输体积；瓶颈分析见批次三尾。

## 批次二：Overview 趋势图改造（TimelineChart）

- **双模式**：All Years = 年×类别堆叠趋势；选具体年 = 该年各能源类别一根柱。
- **指标切换** Project Count / Capacity（同 EntityChart 样式），作用两个视图。
- **口径**：活动模型——项目在其有里程碑的每个年份各计一次；具体年取"当年有里程碑"的项目。容量模式隐藏无 MW 类别（储能/输变电/制造）。
- **配色**：去掉原来的"揉灰"（`softenHexColor`），改用类别原色，与地图/列表/表格/donut 徽章一致。
- **动态标题**：`Annual Project/Capacity Trend`、`{Y} Projects/Capacity by Type`。
- 影响：[TimelineChart.tsx](../../s04_web_visualization/src/components/charts/TimelineChart.tsx)、[OverviewPage.tsx](../../s04_web_visualization/src/pages/OverviewPage.tsx)（传入 `year`）、i18n（`chart.timelineTitle` 拆成 `trendCount/trendCapacity/byTypeCount/byTypeCapacity`）。

## 批次三：概念口径说明 + KPI 标签订正

- **KPI 标签订正**：顶部第一张 KPI 卡英文 `Project Milestones` → **`Active Projects`**（该卡数字一直是"项目数"而非里程碑数，旧标签名实不符；中文"活跃项目数"本就正确）。
- **Overview 蓝色 Note 重写**（中英同步）：讲清 milestone（一个项目经历多个里程碑：签约/开工/完工/收购）/ project / event 三个概念，并点明**KPI（活跃项目数）与下方趋势图口径不同**（前者=区间覆盖当年，后者=当年有里程碑），以及**下载 CSV 为事件级**（一行=一事件×一中方企业）。按用户决定：两个口径不强行统一，只说明。
- 影响：i18n `overview.kpiActive` / `overview.banner`（en/zh）。

### 附：为什么 JSON 4,414 项目前端只展示 1,497（真实数据复算，首个命中归因）

| 规则（代码顺序） | 筛除 |
|---|---:|
| 中国/港澳台 | 40 |
| 无可见里程碑（事件映射不到 4 大状态） | 608 |
| 最后里程碑早于 2022（时间基线） | 925 |
| 隐藏类别（输变电315/火电259/制造127/核电9） | 710 |
| 中方主体未知 | 329 |
| 容量类别但缺容量 | 305 |
| **合计筛除 / 保留** | **2,917 / 1,497** |

结论：主因是**2022 时间基线**（无里程碑 608 + 早于2022 925 = 1,533，占筛除量 53%）＋ 主动排除的非可再生/非发电类别 710；其余 674 为数据质量闸门。属既有设计，非本次改动。
