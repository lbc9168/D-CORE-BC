## Hotfix（T11 验证中发现并修复）

- **bug**：`json_exporter.export_json` 只反序列化 `all_entities` / 两个 links 字段，**漏了 `stage_events`** → `projects_flat.json` 里 `stage_events` 是 JSON **字符串**而非数组。前端类型为 `StageEvent[]` 却拿到字符串，会在运行时静默坏掉（趋势图空、状态徽章 "—"、Status 筛选失效）。typecheck/build 不校验 JSON 内容，故各任务 code review 均未发现；T11 数据断言（"multi-stage: 4373" 异常 = 把字符串长度当数组长度）暴露了它。
- **fix**：`json_exporter.py` 的反序列化列表加入 `("stage_events", [])`。重生成后 `stage_events` 为对象数组，真·多阶段项目 515 个，0 malformed。提交 `fix(s03 S4.1): json_exporter 反序列化 stage_events 为数组(前端需对象数组)`。
- **教训**：纯 code review + typecheck/build 无法捕获"JSON 输出形状 vs 前端类型"的契约偏差；后续应加一个校验 `export_json` 输出 `stage_events` 为 list 的 s03 单测（留作 v2.1 硬化项）。
