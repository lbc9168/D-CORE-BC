## 全量审计后的证据绑定与去重门控收口

### 2026-08-22

- **涉及模块**：S01B S3/S4/S34/S5 Prompt 与确定性后处理、S01B 发布门禁和人工复核队列、S02A 去重确认。
- **做了什么**：没有重写整条 Prompt，只新增一段共用的短项目证据规则，并在 S3/S4/S34 输出中增加仅供当次校验的 `Financing Evidence` / `Participation Evidence`。证据必须是原文连续引文，且项目锚点与目标项目共享项目专名、场址或容量；融资工具必须与锚点同分句，参与角色必须与项目锚点、原文企业名同分句。两个临时字段在后处理后移除，不进入 `projects.db` 或主库，也没有 schema 迁移。
- **为什么**：全量审计发现主要错误不是枚举定义不足，而是同一篇多项目新闻中把某项目、某企业或背景段落的证据复制给其他关系；36 条旧 Equity Financing 均没有严格项目股权融资工具证据，Blended 也常由不同项目或不同企业的事实拼接。将约束放在短 Prompt 契约和可验证的 Python 门控上，可避免继续堆叠长例子。
- **融资规则**：银团、银行财团贷款归 `信贷融资`；债券归 `债券融资`；只有发行股份、认购股份、增资或资本金出资等项目融资工具才归 `股权融资`；明确属于目标项目的赠款/资金援助归 `其他`；至少两种已绑定工具才归 `混合融资`。股权收购/持股只可支持企业的股权参与角色，不能自动生成项目 Equity Financing；组合层面的泛称援助、泛称融资和未绑定工具一律为 `Unknown`。
- **企业参与规则**：每条关系按“目标项目—原文具体企业—参与角色”校验。`投融资+EPC` 同时有同一企业的股权与 EPC 证据才保留；只有 EPC 证据改为 `EPC总承包`，只有股权证据改为 `股权投资方`，两者皆无才为 `Unknown`。能确认直接参与、但角色不明时保留企业并写 `Unknown`；无法证明企业直接参与目标项目时移除该关系，并以 `reason_type=entity_relation` 进入人工复核。若因此没有任何有效中企，项目在复核前不发布。
- **S5 角色锁定**：S5 不再建议或覆盖 `involvement_type`，只保留项目阶段纠偏，防止摘要阶段绕过逐实体证据门控或用单一角色覆盖多实体。
