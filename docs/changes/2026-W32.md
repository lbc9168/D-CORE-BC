## Golden Standard Studio 富金标准契约

- 新增独立 Studio 的 Pydantic 富金标准模型：字段五态、文章证据、项目实体角色、候选包、难度评分和数据集 manifest。
- 字段状态仅包含 `present`、`not_mentioned`、`not_applicable`、`uncertain` 与 `needs_adjudication`；`unreviewed` 仅表示复核库草稿的文章状态。
- 发布边界要求文章已复核并拒绝任何 `needs_adjudication` 字段；`uncertain` 可保留在富金标准中，供后续投影标记为评测不适用。
- 新增唯一 FIELD_REGISTRY，集中定义 19 个审阅字段的类型、证据要求和评测指标。
- 补充字段边界回归覆盖：`present` 无值、无效证据偏移及无效文章 SHA-256 均被拒绝。

## Golden Standard Studio 只读数据源

- 新增 `SourceRepository`：以 SQLite URI 只读模式和 `query_only` 连接 raw-news、extraction 与主库，读取不会修改导入标记或源库。
- 新增不可变文章与当前项目标签快照；保留原始列值并提供仅作空白清理的展示值，事件来源链接可映射至主库项目/实体，未导入记录回退 extraction 标签。
- 数据集可记录三个源数据库的 SHA-256 逻辑快照哈希；覆盖只读拒写和读前/读后源库哈希不变的回归测试。
- 修正只读源库边界：extraction 回退仅读取 `imported_to_s02a` 为 0/NULL 的待导入行；损坏的事件 `source_links` JSON 严格拒绝，不作裸 URL 回退。
- 源库哈希改为只读事务中的确定性逻辑快照（schema + 排序表行），可捕获已提交但仍位于 SQLite WAL 的内容；补充 WAL、映射不可变性和导入标记回归覆盖。
- 主库标签按 `project_events.id`、extraction 回退按行 `id` 显式升序，避免 SQLite 查询计划改变返回顺序；补充等价行反向插入仍产出相同逻辑快照哈希的回归测试。

## Golden Standard Studio 确定性 Pilot 抽样

- 新增按 source link 去重、按稳定 sample ID 排序并以固定 SHA-256 随机值抽取的分层抽样器；相同候选集合及种子不受输入顺序影响。
- 抽样先满足严格负样本配额与稀有类别最低配额，再以风险权重执行确定性 reservoir fill；候选池或组合配额不可行时明确、稳定地报错，不会静默降低覆盖要求。
- 每个入选样本保留类别/风险标签、纳入原因、固定种子和 intended split；60 篇 Pilot 固定为 development/regression/challenge = 36/17/7，250 篇正式集固定为 150/70/30。
- 新增 manifest 生成器，稳定排序 sample ID 与来源快照哈希，并拒绝混合抽样种子或重复 sample ID。
- 修正零负样本配额：负样本配额满足后（包括 quota=0）风险加权填充一律排除其余负例；补充全默认类别下限和高风险填充确定性回归。

## Golden Standard Studio 复核存储、审计与备份

- 新增独立 `ReviewStore` SQLite 边界：样本、规范 Pydantic JSON 草稿、候选包、字段决定、结构修订、审计日志、复核会话与 schema 元数据均落在专用 review DB，不触碰生产数据源。
- 所有人工字段、结构、开始复核与确认操作使用 `BEGIN IMMEDIATE`；安全的两段 `gold_project_id.field_name` 路径会在写入前校验，异常时整笔事务回滚，不残留半写草稿或审计事件。
- 每次决定均保留旧/新 canonical JSON、操作者和时间；结构编辑以乐观 revision 控制并永久保留历史项目 ID，删除后重新新增会自动分配从未用过的新 ID。
- 已确认文章从队列移除；`needs_adjudication` 字段会阻止确认；最近复核会话可跨进程恢复，队列按低难度和 sample ID 稳定排序。
- 备份改用 SQLite 原生 `Connection.backup`，对副本执行 `integrity_check`、八张 review 表的精确行数比对和 audit-log 尾 ID 比对；任一校验失败即抛错。
- 审计保真修复：候选包 upsert 在写入前读取既有 canonical bundle，并将完整旧/新 JSON 一并审计；`AuditEntry` 新增完整解码的 `old_payload/new_payload`，同时保留 `old_value/new_value` 的紧凑展示兼容层，因此相同值但证据、字段状态或 evidence_required 改变也可精确追溯。

## Golden Standard Studio 四路候选与缓存

- 新增内容寻址候选缓存：键明确包含文章 SHA-256、来源、来源/模型版本、prompt hash 与解析器/policy 版本；每条 JSON 记录以唯一临时文件写入并原子替换，支持安全的并发写入。
- 新增四路候选编排：数据库当前标签、生产 staged extractor（复用 `eval.predict.flat_prediction`）、独立审校模型和确定性解析器均输出统一 `CandidateValue`/`CandidateBundle` 契约；任一路超时、异常或无效 JSON 只写入结构化错误，不阻断其它候选。
- 审校 prompt 只包含不可变文章快照，编排层不会向审校 runner 传递数据库或生产候选；独立性违规显式记录为错误。
- 确定性候选复用现有 capacity、储能和 `energy_taxonomy_v1` 分类策略；容量解析先从文章选取候选装机短语，避免全文中的 MWh 储能量被误作为产能上下文。

### Review follow-up：缓存与候选契约加固

- 缓存读取将所有非对象 JSON、键不匹配、候选来源/版本不匹配、无效 UTF-8 和 Pydantic schema 失效记录直接忽略为 cache miss；读取绝不重命名、删除或覆盖当前路径，避免并发替换场景下的 TOCTOU 风险。
- 缓存只保存 `status="ok"` 的候选；超时、provider 异常、无效 JSON 和确定性契约错误都不持久化，下一次 build 会重试该来源。
- 独立审校 provider 必须且只能提供对象顶层 `projects` 列表，缺失键、未知顶层键、错误类型或无效嵌套 `GoldProject` 一律返回结构化 `invalid_json`，不会伪装为成功的空答案。
- review prompt hash 改为 SHA-256(`prompt version + 全部静态 instructions + response schema`)，不含已由文章 SHA-256 覆盖的逐篇标题、正文或日期。
- 候选编排在执行前验证四个 runner source name 恰为 database/production/review/deterministic 各一个，拒绝未知、重复或缺失来源，防止 bundle 键静默覆盖。
- review prompt 改为单一 canonical template，完整包含静态说明、schema、字段标签与分隔符；其 hash 覆盖该完整模板和显式版本，而逐篇原文仍仅由 article SHA-256 区分。
- canonical review prompt 现用单次正则回调渲染四个精确 token；标题、日期或正文中即使出现任何 `__ARTICLE_*__` token 也只会作为原文保留，不会被后续字段替换。

## Golden Standard Studio 证据、冲突、难度与抽检

- 新增证据定位边界：`EvidenceSpan` 先验证原文 SHA-256 与精确 quote/offset；失效时只允许按 quote 唯一或唯一最近位置重定位，重复且无足够 offset 线索时明确进入歧义人工复核，找不到 quote 则阻断。
- 新增 FIELD_REGISTRY 驱动的候选冲突报告：日期与枚举精确比较，数值按 ±5% 比较且零值仅与零值相等，集合按归一化集合比较，项目名与开发商按 Unicode/常见公司后缀归一和模糊相似度比较；候选 source 错误保留为上下文而不伪装成字段值。
- 新增确定性难度评分，公开记录项目数、类别、缺必要证据、多金额、多实体和单源支持的固定权重及对应风险标签；储能语境与来源失败也会显示为风险标签，禁止黑箱置信分数。
- 高一致项抽检使用 `SHA-256(seed:sample_id)` 的固定 draw；ReviewStore 将每个风险标签的抽检率存入 `studio_meta`，审计发现错误时该标签增加 0.10，最高 1.0。

### Review follow-up：项目身份对齐与重叠证据

- 候选 `gold_project_id` 仅为来源内部标识，跨来源比较现固定以 database/production/review/deterministic 的稳定优先级选择参考来源，并按 `project_name` 先作归一精确匹配、再使用同一保守名称模糊语义匹配；不再按候选列表位置配对。
- 项目名重复、模糊匹配不唯一或完全无法匹配时输出显式 `project_alignment_ambiguous` / `project_alignment_unmatched` 结构冲突，且该项目不再继续产生按位置推断的字段冲突；来源顺序互换的同一多项目候选保持无误报。
- quote 搜索现包含重叠 occurrence（如 `aaa` 中的 `aa` 位于 offset 0 与 1），因此此类证据定位会安全地转入歧义人工复核。新增 0%/100% 抽检边界测试，并保留默认、+0.10 与 1.0 cap 的 review DB 元数据回归覆盖。

### Review follow-up 2：全局二分图项目匹配

- 跨源模糊项目对齐不再贪婪消费候选项：先保留双方各唯一的 normalized-exact `project_name`，再为其余项目构建全部保守 fuzzy edge，并按连通分量求最大基数的一对一匹配；分量独立时该结果等同全图最大匹配。
- 仅当最大匹配唯一时才接受该分量的字段比较；多个同样完整的匹配会以 `project_alignment_ambiguous` 显示整个受影响分量并跳过字段比较。项目名/列表排列变化不影响结果，唯一精确 pair 会优先保护后续 fuzzy pair。
- 为避免复杂文章的排列组合爆炸，任一 fuzzy 连通分量任意一侧超过 8 个项目即安全降级为 `project_alignment_complex` 人工复核，不作自动字段配对。

## Golden Standard Studio 本地复核 API

- 新增显式 FastAPI 本地接口：稳定队列、单文章及候选冲突上下文、开始复核、完整项目结构替换、字段决定、确认、裁决与完整审计查询；不接受任意文件路径或 SQL。
- 结构替换以完整有序项目列表和 `base_revision` 执行，乐观并发冲突稳定映射为 HTTP 409；未知样本映射 404，其余契约与领域校验映射 422。
- API 只持有注入的独立 `ReviewStore`，默认审计操作者为 `local-reviewer`，可用受限单行 `X-Review-Actor` 标记本地人工会话，无法通过请求指定源库或执行 SQL。
- 确认会额外校验字段注册表中所有已填关键字段的文章证据，并阻断 `needs_adjudication`；裁决只能原子替换待裁决字段，拒绝再次写入待裁决状态，并在审计中以独立 `adjudication` 动作保留完整 before/after payload。
- API 回归覆盖队列顺序、稳定 ID/structure revision、409/404/422 映射、字段及裁决审计、确认保护、候选冲突序列化，并验证三份源 SQLite 文件在 API 操作前后哈希一致。

### Review follow-up：确认与裁决原子性

- `ReviewStore.confirm_article` 现将“尚未确认”、未解决冲突/待裁决、字段注册表要求的非空证据、以及每个关键字段证据 SHA-256 必须等于当前文章 SHA-256 的检查，全部放入同一 `BEGIN IMMEDIATE` 事务；Web 端点不再预读或预检草稿。
- 普通 `save_field_decision` 可以将字段标记为 `needs_adjudication`，也可以保留该状态作补充记录，但不能把一个已待裁决字段改为任意最终状态；只有原子 `adjudicate_field` 可解除它，并同步写入字段决定和独立 `adjudication` 审计来源。
- API 不可变性测试改为创建真实 `StudioConfig` 三源 SQLite、经 `SourceRepository` 读取文章和当前标签后种子化草稿，再将该 repository 注入 app；完整路由操作前后比较这三份配置源库的逻辑快照哈希。

### Review follow-up 2：已确认草稿不可变

- 新增明确的 `ReviewedRecordError`：`save_field_decision`、`adjudicate_field`、`save_structure`、`start_review` 与重复确认均在各自 `BEGIN IMMEDIATE` 事务加载当前草稿后拒绝已确认记录，不会隐式降级、重开或追加审计事件；API 将此领域错误稳定映射为 HTTP 409。
- 回归覆盖确认后的字段、结构、裁决和开始复核操作，逐项验证 `RichGoldRecord` payload、structure revision 和 audit tail 均不变；API 覆盖四个端点的 409 契约。
- `candidate_bundles` 仍是对候选来源的观测性/审计性元数据：它们不修改富金标准草稿，因而可在确认后记录或更新，但不能重开、改写或影响已确认 gold 内容。

## Golden Standard Studio 冲突优先本地复核界面

- 新增 FastAPI 服务端模板的 `/queue` 与 `/review/{sample_id}` 页面；左栏只显示可选的只读原文快照、元数据与已确认证据高亮，右栏固定按项目结构门控、一致候选折叠、冲突、低置信字段和文章确认排序。
- 每个字段卡均展示人工 review DB 草稿及 database/production/review/deterministic 四路候选的值与状态；候选文本经 DOM text node 渲染，不作为 HTML 注入。
- 结构确认会在当前浏览器会话中保留；字段编辑采用 650ms 输入去抖和失焦保存，服务器失败会显示状态并保留可重试操作。确认按钮只在 API 返回成功后显示已确认，拒绝时草稿保持未确认。
- 提供 A/E/K/X/Enter 快捷键（接受建议、编辑、保留数据库、标记证据问题、确认）；input、textarea、select 与 contenteditable 获得焦点时均不触发。负样本路径先原子保存空项目结构，再请求服务器确认。
- 新增页面契约与真实 Chromium 冒烟：覆盖持久化刷新、编辑态快捷键保护和服务器拒绝确认；本地下载 Playwright Chromium 运行，不新增 Node 构建或部署项目。

### Review follow-up：对齐、结构裁决与本地服务安全

- 文章 API 新增服务端 `field_candidates` 投影：候选项目先以 Task 7 的名称精确/全局模糊匹配对齐到 rich-gold `gold_project_id`，再向 UI 暴露来源项目 ID、原始索引、字段值和证据；前端不再按任一候选数组位置取值。结构冲突另行输出，保留 project-count 与无 project index 的 ambiguous/unmatched/complex 诊断。
- 新增持久化 `structure_gate`：若最新候选包含结构冲突，只有候选包之后保存的完整结构 revision 才能解除门控；`confirm_article` 在同一 `BEGIN IMMEDIATE` 事务内复核该条件，直接 API、Enter 与界面按钮均不能绕过。
- 复核页新增有序结构编辑器（项目名称、增加/拆分、移除/合并、完整列表保存）以及折叠审计面板；所有字段行动仅使用服务端已对齐投影，快捷键仅作用于当前聚焦卡片。
- 本地页面仅将绝对 HTTP(S) 原文链接渲染为可点击链接，候选/审计文本均经 textContent；本地 app 添加 same-origin CSP。只读 `SourceRepository` 连接允许 FastAPI/Uvicorn 处理线程读取，从而能在真实浏览器中渲染原文与 evidence 高亮，仍保持 SQLite 只读 URI 与 `query_only`。
- 新增乱序双项目 API/Chromium 回归、持久结构门控与 Enter 防绕过回归、真实 SourceRepository 原文证据高亮回归；浏览器测试选择非 Chromium 禁用端口，避免随机端口导致的 `ERR_UNSAFE_PORT` 偶发失败。

### Review follow-up 2：并发与审计单调性

- `SourceRepository` 为共享的 `check_same_thread=False` 只读连接增加 repository 级可重入锁和关闭状态；文章、标签（含主库/提取/实体链路）、快照哈希和 close 均串行化，逻辑哈希的 BEGIN 至 ROLLBACK 保持同一锁范围。并发 ThreadPoolExecutor 回归混合读取与哈希后再验证关闭语义。
- 结构门控不再比较墙上时钟：candidate bundle 与 structure decision 均在各自 `BEGIN IMMEDIATE` 事务中追加 audit_log，确认时比较最新结构冲突 candidate audit ID 与最新结构 decision audit ID。候选→结构可放行，结构→新候选必重新阻断，即使所有时间戳完全相同。
- 候选字段投影会剔除与当前文章 SHA-256 不一致的 evidence span 并标记 `evidence_warning`；前端显示警告且不会接受该候选。`present` 对 `not_mentioned`/`uncertain` 现产生显式字段状态冲突，避免被折叠为一致项。
- 快捷键按当前焦点或当前指针卡片定位，失焦或全局控件操作会清除目标；Ctrl/Meta/Alt 组合键和重复事件无副作用。

### Review follow-up 3：人工草稿证据快照边界

- 复核页高亮仅使用 `span.article_sha256 === state.article.article_sha256` 的人工草稿 evidence span；即使 quote 与 offset 仍然匹配，过期 span 也绝不在当前原文中标记。
