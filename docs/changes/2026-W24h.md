## 背景
S4.1 把年份滑块从「双柄范围」改为「单柄参考年 Y」（截至 Y 的快照语义）。用户复看后倾向双柄——可框选一个时间范围。本次改回双柄，但**保留 S4.1 的 status-at-year 模型**：状态/地图配色/趋势图一律按**范围结束年 end** 计算（用户拍板）。

## 改动（仅 s04 前端，5 文件）
- **`types/index.ts`**：`FilterState.refYear: number | null` → `yearRange: [number, number] | null`（null = 不限年份；状态按 end 年算）。
- **`contexts/DataContext.tsx`**：
  - `applyFilter` 年份存在性：单点落区间 → **区间交叠**（项目 `[first,last]` 与所选 `[start,end]` 有交叠才显示）。
  - 状态筛选：`statusGroupAt(p, refYear)` → `statusGroupAt(p, yearRange ? yearRange[1] : null)`（按 end 年）。
  - `statusGroupOf`（地图配色/趋势图驱动）同改为按 end 年。
  - `DEFAULT_FILTER.refYear: null` → `yearRange: null`。
- **`components/filters/FilterBar.tsx`**：`SingleYearSlider` → 还原 `YearRangeSlider`（双柄，复用既有 `.dual-range-input` CSS）；标签改 `filter.yearRange`，两端显示 start/end。
- **`index.css`**：删除已无引用的 `.single-year-input` 样式块（`.dual-range-input` 原样保留）。
- **`i18n/en.ts`+`zh.ts`**：删除已无引用的 `filter.year` 键（`filter.yearRange` 已存在）。

## 数据→部署链路核查（用户问"是否自动")
- **自动的部分**：`s03 run_export`（main.py:139-146）把 `events_export.csv` + JSON 同时写入 `s03/data/output` 与 `s04_web_visualization/public/data/`；`vite build` 自动把 `public/` 拷进 `dist/`。即 **build 产物 `dist/data/events_export.csv` 自动带上，无需手工打包**。
- **断点**：`*.csv` 在 `.gitignore`（第 20 行）→ events_export.csv **不进 git**。若线上是「服务器上 git pull 再 build」则永远没有此文件；当前线上是「手工交付构建产物给管理员」，这次只传了 JS/HTML 漏了 `data/`。
- **结论给用户**：自动链路在 `export → public/data → vite build → dist/data` 这段成立；要彻底免手工，部署时务必上传**整份 `dist/`（含 `data/` 文件夹）**，而不是只挑 JS/HTML。
