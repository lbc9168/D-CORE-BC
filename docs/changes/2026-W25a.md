## 背景 / 为什么

`docs/status/` 本意只记录"每个模块当前是什么、怎么运行"，但随 web 开发推进，逐渐混入大量带日期的变更记录，越写越乱（`s04.md` 已达 334 行、几乎全是 changelog；`s01b.md`/`s02a.md`/`s03.md` 顶部与底部都堆着历史条目）。根因是 CLAUDE.md 旧「改动规则」只说"同步更新 status 和 changes"，没区分二者写法。本次把"快照"与"历史"彻底分离，并把规则写死进 CLAUDE.md 防止再次劣化。

## CLAUDE.md

- 合并旧「项目说明」+「改动规则」为一节「**文档与日志规则**」，明确：
  - `docs/status` = 当前状态快照、**覆盖式**、固定文件集（overview/pipeline + 每模块一份）、统一 5 小节模板，不写历史。
  - `docs/changes` = 变更日志、**追加式**、不改旧条目。
  - 同步触发：以"有意义的工作单元"为粒度；只有改变模块当前功能/运行方式/输入输出契约时才动 status。
- 删掉一个空的 `## ` 标题。
