### feat(s02a): 新增实体名称归一化工具 entity_normalizer

**问题：** `chinese_entities` 表中同一家中国企业存在多种写法（如"中国电建"与"中国电力建设集团"、"正泰新能"与"正泰新能源"），影响数据质量和统计准确性。

**改动：**

- `src/s02a_duplicate_merger/entity_normalizer.py`（新增）：独立的后处理脚本，三信号候选筛查 + Gemini LLM 批量确认 + Union-Find 归一化

  **三信号逻辑：**
  - Signal 1：`token_sort_ratio ≥ 80%`（词序无关相似度）
  - Signal 2：`partial_ratio ≥ 90%`，附加长度比约束 ≤ 2.5×（排除父公司 vs 远房子公司误匹配）
  - Signal 3：子序列缩写检测——短名（4~8字）所有字符按序出现在长名中，且前3字一致、长度比 ≤ 0.68（专门捕获"中国电建 ↔ 中国电力建设集团"类缩写，两者 ratio 仅约 62%，两个数值信号均无法捕获）

  **Special 处理：** Unknown / 未知 / 不详等变体统一归一为 `"Unknown"`

  **LLM 批量确认：** 候选对分批（25对/批）发送 Gemini，确认是否指同一公司并选定规范名称；Union-Find 合并已确认组，更新 `implementing_entity` 和 `subsidiary_name` 两列

- `pyproject.toml`：注册入口点 `normalize_entities`

**使用方式：**
```bash
cd s02a_duplicate_merger
uv run normalize_entities --preview   # 预览候选对，不写入数据库
uv run normalize_entities             # 正式运行，约 2-4 分钟（~29 次 LLM 批次）
```

> 运行完成后需重新执行 `uv run run_export`（s03）和 `npm run build`（s04）使结果生效

### fix(s04): 储能/输变电建设类别排除装机容量统计（#17）

**问题：** 储能（ES）和输变电建设（TX）项目的容量单位不是 MW，混入装机容量聚合统计会产生严重误差。要求：项目数统计仍计入，装机容量统计中排除。

**改动：**

- `src/utils/capacityPolicy.ts`（新增）：定义 `NO_CAPACITY_CATEGORIES = new Set(["储能", "输变电建设"])` 和 `hasCapacity(category)` 辅助函数，集中管理口径，扩展时只需改一处
- `src/contexts/DataContext.tsx`：`useCountryStats` 在 `colorBy==='capacity'` 时跳过 ES/TX 类别（世界地图容量着色）
- `src/components/map/ProvinceMap.tsx`：`provinceValues` 在容量模式下跳过 ES/TX（省级地图容量着色）
- `src/components/charts/EntityChart.tsx`：企业装机容量累加时跳过 ES/TX（右下角企业装机排名）

**不受影响：** 所有"按项目数"统计模式（ES/TX 仍正常计入）；ProjectList / ProjectDetail 中的单项目容量显示
