## 背景 / 为什么

W27e 完成 s01b 非能源治本四层防御，并把 `sweep_nonenergy --apply`（真实 `projects.db` 回溯清扫）**GATED 待用户复看 dry-run CSV**（2026-07-03 dry-run 命中 535/11106）。本 session 执行该 GATED 项。

复看 dry-run 时发现 **误杀一类真发电项目：垃圾焚烧发电 / 生物质（WtE）**。对照主库 `bri_re_database.db` 证实 WtE 属**在册在网**类别——`canonical_projects` 中有 **58 个「垃圾焚烧发电」项目**（生物质/综合能源/火电/地热及余热）。dry-run 会错杀其中 3 个物理项目（对应 canonical 均为保留态）：

| dry-run ids | 项目 | 真发电证据 | 主库 canonical |
|---|---|---|---|
| 3171, 3172 | 澳门垃圾焚化中心第三期扩建 | `capacity_mw=200`；摘要"年发电量超2亿度…绿色电力" | MAC-HB-0001 |
| 6839, 6840 | 塞尔维亚米特洛维卡焚烧锅炉岛EPC | 摘要"热电联产" | SRB-GT-0001 |
| 2191-2194 | 澳门有机资源回收中心 | 生物质，"转化为再生能源" | CHN-BM-0001 |

**根因**：护栏 Rule 3（吨/年产能判非发电）**只在项目名称里找发电语义**。存活的 58 个 WtE 名称均含「发电」；这 3 个名称是"焚化中心/焚烧锅炉岛/有机资源回收"无「发电」字样，其发电信号在摘要或 `capacity_mw` 字段，被 Rule 3 忽略。

## 改动内容

### `guardrails/nonenergy_check.py`（Rule 3 修正，走 TDD）

- 新增 `_TONNAGE_EXEMPT_CATEGORIES = {"新能源制造业", "生物质", "地热及余热"}`：这些类别以处理吨量计装机为正常口径（垃圾焚烧发电/余热按处理量计），不再按吨/年判非发电。
- 新增 `_GENERATION_EVIDENCE = ["发电", "绿色电力"]`：名称无「发电」但**摘要**证明确为发电项目时放行。
- Rule 3 判定改为：`category not in _TONNAGE_EXEMPT_CATEGORIES and capacity_is_tonnage(...)` 且 `name` 无 `_POWER_WORDS` 且 **`name+summary`** 无 `_GENERATION_EVIDENCE` → 才排除。
- **关键设计**：只查 `name+summary`，**不查 `capacity_details`**——后者可能含辅助供电「风电+太阳能」等误导词（如壳牌油气平台 id 46，`capacity_details` 写"风电+太阳能混合供电"但实为油气平台，须仍排除）。亦不据 `capacity_mw` 判定（它可能是毒值，如哈法亚GPP 天然气处理厂 `capacity_mw=2250`）。

### `tests/test_nonenergy_check.py`（回归夹具）

- `WASTE_TO_ENERGY_LEGIT`（4 例，不许误杀）：澳门垃圾焚化中心（绿色电力）、奥什市垃圾科技处置（垃圾发电工程）、澳门有机资源回收（生物质）、塞尔维亚焚烧锅炉岛（地热及余热）。
- `TONNAGE_NONENERGY_STILL_EXCLUDED`（2 例，防放行过度）：哈法亚GPP（毒值 mw + 天然气摘要）、壳牌HI油气平台（details 含辅助「风电+太阳能」诱饵）。
- TDD：先见 4 例 RED（Rule 3 返回吨/年理由），修后 GREEN。
