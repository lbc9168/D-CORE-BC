## S3+S4 合并为单次 `s34` 调用（已采纳为默认）

**动机**：逐项目阶段 S4(实体) 与 S3(金融) 各发一次 `content[:12000]`，对每个具名项目重复发正文两次。合并成一次调用可省一次正文重发。

- **新增** `prompts/s34_entity_finance.py`（`build_s34_prompt`：A 实体规则[S4 1-6] + B 金融规则[S3]，输出 chinese_entities[] + 金融字段同级）+ `stages/s34_entity_finance.py`（`run_s34`/`validate_s34`：实体母子公司归一、投资额 bri_parse、切出 finance）+ `tests/test_stage_s34.py`。
- **orchestrator**：per-project 循环加开关 `S01B_MERGE_S34`（默认由 `.env` 开）。开启时 named 项目走 `s34` 一次调用（跳过单独 S3）；**unnamed 路径与关闭时行为一字不变**（保 P2 的占位实体逻辑）。
- **路由**：`s34` 经 StageRouter 走 DeepSeek（`.env` 的 `S01B_STAGE_PROVIDERS` 含 `s34:deepseek`）。
- **eval**：版本哈希纳入 `S01B_MERGE_S34` 与 `s34_entity_finance` prompt 源，混合/合并配置缓存隔离。

**A/B（hybrid，各单轮）**：合并 weighted **0.7752** vs 分开 0.7547；实体 name/role 合并更高、category/investment 分开略高——**双向差异均在单轮噪声内，无单向退步**；**结构性省 ~1/3 DeepSeek 调用**（~12→~8/批）。详见 `docs/status/eval.md`「S3+S4 合并 A/B」。

- **采纳为默认**：`.env` 设 `S01B_MERGE_S34=1` + `S01B_STAGE_PROVIDERS=...,s34:deepseek`。关掉开关即回原 S3/S4 分开行为。
- **验证**：root + s01b 全测试绿（含新 s34 测试 + P2 的 unnamed/exclude 测试无回归）。
