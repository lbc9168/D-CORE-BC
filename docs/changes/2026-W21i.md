## 目标

P0 的评测框架按「一文一项目」打分（只取主项目），无法衡量提取器在一篇含多项目文章里的
**枚举 / 拆分 / 合并**能力，也没有 per-entity 角色。P0.1 升级为**一文多项目**：金标准与预测都以文章为单位、
内嵌 projects[]，先做项目对齐，再逐项目打字段/实体分，新增项目集合 P/R/F1 与角色准确率指标。

## 改动模块 `eval/`（仓库根）

- **`eval/metrics.py`**（Task 1–3，TDD）：
  - 新依赖 **rapidfuzz**；新增 `align_projects(pred_projects, gold_projects, threshold=80)`——按项目名
    `token_set_ratio` ≥ 80 做**贪心对齐**，平局看 `_attr_bonus`（同 category +1、capacity ±5% +1），
    返回 `(matched[(pi,gi)], unmatched_pred, unmatched_gold)`。
  - 新增 `score_entities(pred_entities, gold_entities)`——中企**名字集合** P/R/F1 + 仅对同名企业比 involvement_type，
    返回 `(name_p, name_r, name_f1, role_correct, role_matched)`；两边皆空记满分。
  - 新增 `score_article(pred, gold)`：status 闸门（文章级，错或 gold 非 valid 则不打分）→ `align_projects` →
    对每个匹配项目打 3 枚举（category/project_stage/financing_model）+ 2 数值（capacity_mw/total_investment_usd，±5%）
    + `score_entities`；返回 `{status_correct, scored, project_set:(matched,pred_n,gold_n), field_hits, entity}`。
  - **移除旧** `score_record` / `ENUM_FIELDS` / `NUMERIC_FIELDS` / `entity_prf`；改用 `PROJECT_ENUM_FIELDS` /
    `PROJECT_NUMERIC_FIELDS`。`cmp_status` / `cmp_enum` / `cmp_numeric` 保留。location 记录但不打分。

- **`eval/predict.py`**（Task 4）：`flat_prediction(result)` 改为输出文章级
  `{status, projects:[{project_name, category, capacity_mw, project_stage, location, total_investment_usd,
  financing_model, entities:[{name, involvement_type}]}]}`——返回**全部项目**（不再只取主项目）；非 valid 时
  `projects=[]`。status 映射不变（`valid_project→valid` 等）。

- **`eval/gold_loader.py`**（Task 5）：金标准改**嵌套 schema**。`GoldRecord`= `{source_link, article_id?,
  status(文章级三选一), projects[]}`；`Project`= 5 评分字段 + location + `project_name`（仅对齐）+ `entities[Entity]`；
  `Entity`= `{name(必填非空), involvement_type?}`。`extra="forbid"`，非法行（status 不合法 / 实体缺名字）带行号抛 `ValueError`。

- **`eval/run_eval.py`**（Task 6）：`run_eval` 改用 `score_article`，重写聚合与报告。报告新键：
  `n_scored_articles`、`project_set{matched,pred_total,gold_total,precision,recall,f1}`、
  `fields{field:{correct,total,accuracy}}`、`entity{name_f1_mean,role_accuracy,role_matched_total}`。
  **weighted_total 四分量改为** `status / fields（各字段准确率均值）/ entity_name（name_f1_mean）/ entity_role（role_accuracy）`，
  等权（`WEIGHTS`），无数据分量丢弃后重新归一化；**project_set 不进 weighted_total**（单列衡量枚举/拆分）。
  对比打印 `_metric_rows` 增加 `project_set.f1` 与 `entity.role_accuracy`。

- **`eval/build_draft.py`**（Task 7）：草稿改**一项目一行**——一篇多项目文章拆多行，`source_link` / `status` 逐行重复；
  新增列 `ai_project_name` / `project_name`；`no_chinese` / `irrelevant` 与负样本桶为单行、项目列留空。

- **`eval/csv_to_gold.py`**（Task 8）：`convert` 改为**按 `source_link` groupby 聚合**多行 → 一篇文章
  `{status, projects:[...]}`（每承载项目的行→一个 project）。`_parse_entities` 解析 `名字(角色); 名字(角色)`——
  **角色取末尾括号组**，故公司名本身可含括号（`中国大唐环境(中国)有限公司(EPC总承包)` → name=`...有限公司`、role=`EPC总承包`）；
  缺名字抛错。status 取该篇各行首个非空，无 status 整篇跳过并告警；写完用 `gold_loader.load` 校验。
  运行命令不变：`python -m eval.csv_to_gold --csv eval/draft.csv --out eval/gold_set.jsonl`。
