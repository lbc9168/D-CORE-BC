## 背景 / 为什么

W27f 诊断量化了 `project_events.project_developer` 语义不可靠（84% 填充率可疑、~180 起「developer=同事件设备商/EPC」硬证据）。按专项计划第①步，先做分层抽样对照原文，验证错误假设、并为后续 prompt 修复攒回归评测集。本次为纯分析 session。

## 做了什么

- 分层抽样 28 事件（seed=42，可复现）：按「developer 与同事件中方实体重名的角色」分 5 层——重名-设备商(6) / 重名-EPC(6) / 重名-投资方(4) / 不重名(6) / 留空(6)；母体（non-excluded events 5247）各层规模 139 / 255 / 539 / 3408 / 906。
- 经 `project_events.source_links` 连回 `s01a_news_crawler/data/raw_news.db` 原文（28/28 全命中），逐条对照原文人工判定 developer 正误，附证据引文。

## 判定结果

| 层 | 结果 | 要点 |
|---|---|---|
| 重名-EPC (6) | **6 全错** | EPC 中标/签约新闻业主几乎从不具名，应留空 |
| 重名-设备商 (6) | 3错 / 2对 / 1存疑 | 两类合法例外：制造业厂主=设备商自建（Hygreen）；PPA 卖电方自持电站（东方日升） |
| 重名-投资方 (4) | 2对 / 1部分 / 1存疑 | 新错误模式：购电方当共同业主（塞尔维亚紫金）；「联合体实施协议」非产权证据 |
| 不重名 (6) | 5对 / 1错 | 错例：融资机构（IFC/ADB）当业主 + 自由文本污染 |
| 留空 (6) | **6 留空正确** | 原文确实不点名业主——无 recall 问题，过填是唯一问题 |

- 加权估算存量填值准确率 ~74%，错误集中在重名-EPC/设备商两层；另见 3 例值格式污染（括注、英文自由文本）。
- 设计含义：① S2 prompt 改证据白名单+留空规则（业主定义/EPC发包方/购电方融资方负面清单/JV拆填）；② 确定性交叉守卫（EPC 重名置空；设备商重名置空但豁免新能源制造业）；③ 守卫须保守——S4 角色标注本身也有错（东方日升被标设备供应商实为 PPA 卖方）。

## 第②步：S2 业主判定规则 + 确定性业主守卫（同日下午，TDD）

### 改动内容

**`prompts/s2_basic.py`（S2 prompt）**：新增「业主判定」小节——业主=产权/股权持有方；证据白名单（显式指认/投资建设/EPC发包方/股权持有收购/特许经营权人/PPA卖电方，卖电方是业主、买电用电方不是）；负面清单（承包商/设备商/融资机构/购电方/审批政府，例外：制造业厂主自建、自有电站售电）；**无证据留空**、禁占位词；JV 拆填各合资方（`;` 分隔，只写公司名，禁括注/股比/自由文本）。输出 schema 新增 `Project Developer Evidence`（≤40 字原文短语）。

**`guardrails/developer_check.py`（新增，Layer 0）**：`clean_developer(developer, entities, category)`——developer 部件与同事件实体（母/子公司名互含 ≥3 字）重名时：纯承包角色（EPC总承包/设计·施工服务方）剔除；设备供应商剔除但豁免新能源制造业；投资类角色（股权投资方/投融资+EPC/BOT/BOOT）一票保留；融资方等保守保留。

**`tools/project_extractor_tool.py`**：valid_project 行组装处接入守卫（清洗在翻译前，省无效翻译调用，剔除记 logger.info）；`extracted_projects` 新列 `project_developer_evidence`（CREATE TABLE + ALTER 迁移 + INSERT，两条写库分支均落 evidence）。

**测试（TDD，RED→GREEN）**：`test_developer_check.py`（11 例，fixture 全部取自抽样真实案例）、`test_developer_check_integration.py`（4 例：EPC 置空落库/投资方存活/evidence 两分支落库）、`test_s2_prompt_developer_rules.py`（prompt 锚点）；`test_resolve_developer_en.py` 一处夹具角色 EPC→股权投资方（该测试考拆串翻译路径，避免与守卫语义纠缠）。**s01b 全量 352 passed**。

### golden 实测（28 篇原文真跑新 prompt，gemini-2.5-flash-lite）

结果 `supporting_docs/developer_prompt_eval_20260704.csv`：

- **10 个硬错误全部消除**：EPC 组 6/6 留空；设备商组留空或改填真业主（AIS GmbH）；融资方（IFC/ADB）留空；塞尔维亚案购电方紫金剔出仅留投资方；3 个「Unknown」占位与全部格式污染（括注/英文尾巴）消失。
- **该保的全保住**：Hygreen（制造业豁免）/Tanco/国家电投（特许权）/SEC/阿根廷核电/EDF;ESB（JV 拆填）。
- **防御纵深起效**：越南一冶案 prompt 仍填总承包方，由守卫在写库前置空（这正是双层设计目的）。
- **已知局限（2 例，接受）**：①澳洲企业 PPA 案（项目名即买方视角）仍填购电方西部镍业（旧值东方日升反而对）；②几内亚德企投资案过度保守留空（recall 损失）。均记录在案，留给第③步存量重估处理。
- 预计新提取填充率从 84% 降至 ~50%（抽样留空组 6/6 证实原文确实不点名业主，无 recall 问题）。
