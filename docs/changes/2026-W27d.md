## s01b 独立运行 `import bri_enums` 崩溃

- **现象**：`uv --project s01b_project_extractor run run_bulk_extract`（docs/status/s01b.md 记录的标准独立命令）在 s01b 自己的 venv 里崩溃：`ModuleNotFoundError: No module named 'bri_enums'`。
- **根因**：`project_extractor_tool.py` 顶部先执行 `from s01b_project_extractor.guardrails.format_checks import ...`（format_checks.py / batch_checks.py 顶部都直接 `import bri_enums`），而"上溯找仓库根并 `sys.path.insert(0, _root)`"那段原本在文件更靠后。s01b 独立 venv 里仓库根不在 `sys.path` 上，导入链先跑到 guardrails 的 `import bri_enums` 就崩了。pipeline 编排能跑通只是因为运行环境恰好已把仓库根加进了 path。
- **做了什么**：把 `_root = next(...); if str(_root) not in sys.path: sys.path.insert(0, str(_root))` 那段（连同说明注释）上移到顶部 import guardrails **之前**（`sys`、`Path` 在文件更早处已导入，可安全前置）。原位置保留 `import bri_enums as enums` 等语句不动（此时 path 已就绪）。集中在此文件前置一次，未给 format_checks/batch_checks 各自加 path 插入（避免重复逻辑散落）。
- **为什么**：guardrails 两文件顶部都直接 `import bri_enums`，所以 `sys.path` 必须在导入 guardrails 之前就绪。
- **验证**：`uv --project s01b_project_extractor run python -c "from s01b_project_extractor.tools.project_extractor_tool import ProjectExtractorTool; print('ok')"`（不设 PYTHONPATH，新建隔离 venv）输出 `ok`，不再 ModuleNotFoundError。
- **影响**：仅动 `project_extractor_tool.py` 导入顺序；纯内部修复，不改变对外行为/输入输出契约，故不动 docs/status。
