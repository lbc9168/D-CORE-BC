## Bug 根因

`entity_normalizer.py` Step 1 的别名→规范名映射**仅从 `implementing_entity` 列构建**（L358-364），
但 `_update_db`（旧 L274-279）把同一映射**同时套用到 `subsidiary_name`**。
若某行 `subsidiary_name` 恰好等于某个 implementing 别名（如"中国电建"），会被错误改写为母公司规范名 → 子公司名被污染。

## Task 1（S5d）· 修 _update_db（TDD）

- 新建 `s02b_entity_normalizer/tests/test_entity_update_db.py`（2 用例）：
  - 用例1：给 implementing 映射 `{中国电建→中国电力建设集团}`，第一行 implementing 被规范化、第二行的 `subsidiary='中国电建'` **不被改写**（返回 `n_impl=1, n_sub=0`）。
  - 用例2：仅传 `sub_mapping` 时才改 subsidiary（`n_impl=0, n_sub=1`）。
  - 先红（subsidiary 被误改 / 无 `sub_mapping` 参数）后绿。
- `_update_db` 签名改 `(_update_db(db_path, impl_mapping, sub_mapping=None))`：
  - `impl_mapping` 只更新 `implementing_entity`；
  - 仅当传入 `sub_mapping` 才更新 `subsidiary_name`（两列映射来源独立）；
  - 批量写改 `executemany`（CLAUDE.md 规则3），用 `cursor.rowcount` 取行数。
- `run` Step 5 调用 `_update_db(db_path, mapping)` 不变（positional → impl_mapping，sub_mapping 默认 None）：subsidiary 归一暂不做，留 v2.1。
