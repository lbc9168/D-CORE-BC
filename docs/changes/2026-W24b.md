## 关键设计决策（留档）

1. **存量回溯被"P3 后全量重建"化解**：草稿原有"存量回溯 vs 仅前向"重大决策，已被用户主线拍板（P3 后做 s02a canonical 全量重建，从 `extracted_projects` 11,909 行重跑）化解——重建即全部存量流经新去重逻辑，无需单独回溯任务。
2. **跨阶段合并语义**：分组去 stage 后 union-find 组可能横跨多阶段。**不折叠成一条**（会丢事件），而是按 `project_stage` 分摊、每阶段内部各自合并、全部打共享 `dedup_group_id`；`_write_to_db` 见相同 gid 直接复用首条 canonical_id（跳过名称匹配，否则低名称分跨阶段对会在 canonical 层重新分家）。落库 = 一条 canonical + 每阶段一条 event。
3. **地点归一化两个消费端**：已知 case 达瓦德密/达旺德米是**批内**记录——重建时 11,909 行同批，Signal 6 锚点必须在候选筛查**之前**拿到 location_norm。故共享逻辑放根 `bri_location.py`，s02a 批内 in-memory 归一（写 `project["location_norm"]`），s02b CLI 落库归一（写 `location_norm` 列供后续增量批次跨批匹配）。
4. **location_norm 只加不覆盖**：`canonical_projects` 加列，未归一留 NULL，消费方"norm 优先回退 location"。s03 全部 `SELECT *`+`dict(r)` 取值，加列不破坏下游（s03 13 测试仍绿）；s03 暂不消费 location_norm（YAGNI，留 s03 重跑时评估）。
5. **模型默认稳定版可 env 覆盖**：`LLM_CONFIRM_MODEL` 原写死 `gemini-3-flash-preview`（preview），改默认 `gemini-2.5-flash-lite`，要换更强模型用 `S02A_LLM_CONFIRM_MODEL` 环境变量，不改代码。
6. **误并防线**：所有新信号只把候选对**送 LLM 确认**，无任何免确认直并路径；Signal 6 有容量 15% + ≥10MW 双门槛；canonical 地点辅助有 `_capacity_guard`（容量差>20% 拦截）前置；LLM prompt 拿不准按"不是"处理；bri_location LLM 失败保守不合并。最终防线是 runbook 的人工抽查。
