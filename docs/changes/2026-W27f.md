## 改动内容（四个交付物）

### 交付物一：缓存审计 CLI（`s01b_project_extractor/tools/cache_hygiene.py`）

- `uv run cache_fix`：六规则扫描缓存键/值——R1 分隔符（多公司串/头衔串）、R2 键含头衔/职位词、R3 键为占位泛指短语（前置过滤，R4-R6 不再重复评估此类键）、R4 键超长(>30字)、R5 值含中文、R6 值含换行/超长/括注噪声；`verified=true` 的键全部豁免。
- `--corrections CSV` 通道：加载 corrections CSV（`cn,en,en_abbr,verified,source`），支持修改现有键的英文值或添加新键。
- 默认 dry-run：输出规范 CSV 报告（`kind=remove_candidate/correction`）；`--apply` GATED（需用户复看后手动执行）。
- **种子 corrections**（`supporting_docs/cache_corrections/2026-07-04-hard-errors.csv`）：4 条已知张冠李戴错译（上能电气/泰豪国际/中国水电/中地海外），`verified=false`，需 campaign 核实后置 `verified=true` 再 apply。

### 交付物二：s01b 翻译入口守卫（`s01b_project_extractor/src/…/tools/project_extractor_tool.py`）

- **ASCII 直通**：`_resolve_entity_en(cn)` 入口若输入已是纯 ASCII → 直接返回原值，不查缓存、不翻译（英文原名不经 LLM 改写）。
- **developer 按分隔符拆串**：`_resolve_developer_en` 按 `DEV_SEP_RE`（`[;；、，,/]`）拆分 `project_developer` 字段，逐家分别翻译，结果以 `'; '` 拼回；两处 developer 调用点均已接入。
- **缓存写入守卫**：多公司串（含分隔符）或超长键（>30字）不写缓存——防止新垃圾键生成。
- **已知取舍**：缓存中 ~30 个 value-added 英文键（如 `"Canadian Solar"→"Canadian Solar Inc."`）属 ASCII，被直通后其增量值（后缀"Inc."/"Ltd."）不再追加——符合「缩写为主」口径（不追求全称精确），已知接受。

### 交付物三：s02b developer 归一（`s02b_entity_normalizer/src/…/developer_normalizer.py`）

- `run(db_path=None, preview=False, apply=False)`：读 `project_events.project_developer` 字段，整值垃圾占位统一为 `Unknown`；非占位值用**部件级三信号**（token_sort≥80 / partial≥90+长度比 / 缩写子序列）筛候选对 → LLM 确认 → Union-Find 归一 → apply 前 `.bak`。
- **裸跑等同 preview**：`uv run normalize_developers`（无 `--apply`）仅展示候选对，不调 LLM、不写库；`--apply` GATED 才写库。
- `uv run normalize_developers`（`pyproject.toml` 新增入口）。

### 交付物四：s02b 英文名回填（`s02b_entity_normalizer/src/…/en_backfill.py`）

- `main()`（CLI 入口）：从 `company_name_cache.json` 以**en_abbr 优先口径**（`cache[cn].en_abbr` 存在则用，否则回落 `en`）回填主库（`chinese_entities.implementing_entity_en/subsidiary_name_en`、`project_events.project_developer_en`）和 `projects.db`（三列同名）。
- **hit 才 update**：缓存命中且 diff 则写，miss 只记录（=campaign 候选池）；ASCII 值与 Unknown 跳过不改。
- **apply 前 .bak**：每库各自备份。
- `--out CSV` 导出明细（列：`status`（hit/hit_multi/miss/partial_miss）+ `action`（update/report_only））；ASCII/Unknown 行不出现在 CSV。

## GATED 执行序列（用户复看后依次操作）

> 以下操作均 GATED，不由本次 commit 自动触发。

① **cache_fix apply**（复看 dryrun CSV 后）：
```bash
cd s01b_project_extractor
uv run cache_fix \
  --cache E:\Projects\BRI_RE_Database_v2\supporting_docs\company_name_cache.json \
  --findings <复看并删掉误报行后的清理报告 CSV（dry-run 产出的 2026-07-04-cache-hygiene-dryrun.csv）> \
  --corrections <复看后的 corrections CSV（种子 4 条，核实后可改 verified=true）> \
```

注意：不传 `--findings` 则只 upsert corrections、不删除任何垃圾键。

## 口径决策备忘

- **缩写为主**：英文名存 en_abbr（"PowerChina"/"中电建"/"SEPCO3"）而非全称。`_cache_en` 以 `en_abbr` 优先，无 abbr 才回落 `en`（缓存只有 en/en_abbr 两个字段）。ASCII 直通不追加后缀全称属同一口径，已知接受。
- **不重建 s02a**：回填直接原地更新三列，不影响 s02a 结构。s02a 重建属 P3 去重分组后续，与本次独立。
- **混合中英文多公司串**：backfill 对非中文段直通（镜像 s01b `_resolve_entity_en` 行为，缩小 miss 池，零错写风险）——终审后定案。
