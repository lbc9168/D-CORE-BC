① 分段控件位置：嵌在 FilterBar 最左侧、年份滑块之前。三段固定宽度，不参与 flex-wrap 换行；选中段白底加投影（cobalt 惯用高亮）。域标签走 i18n 新 key（nav/domain 命名空间），非硬编码。
② Color By 保留原位：着色下拉仍在筛选栏内，但选项随域联动（域1: Project Count / Capacity (MW)；域2 见⑤；域3 见⑨）。
③ ES 保留在域1（已拍板）：储能项目在域1 照常可见、照常不进 GW 聚合；列表规模位显示「50 MW · 56.2 MWh」储能双指标（capacity_mw 为空时的替补显示，小改进）。
④ 域2 隐藏 Project Type 筛选器：域内构成固定（ES + 光储），类别筛选无意义，整个控件不渲染（mockup 中划线仅示意"消失"）。
⑤ 域2 默认 MWh 着色：Storage Capacity (MWh) / Storage Power (MW) / Project Count 三选。真库覆盖：MWh 215/307=70%，MW 105/307=34% → MWh 做默认。图例分箱为真实数据（沙特 32.9 GWh 最大、UAE 16.5 GWh 次大）。
⑥ 域2 = 307 个项目 = ES 178 + 综合能源·光储 129（口径过基线 policy 后）。光储项目同时出现在域1（按 MW 计）和域2（按 MWh 看），两域口径独立、无重复计数。
⑦ 域3 子域 Tab：All / Transmission / Manufacturing 三态，替换掉 Project Type 筛选器的位置。TX 437 + MF 161 = 598。
⑧ 域3 隐藏 Status 筛选：tx/mf_flat 无 stage_events 时间线，只有当前状态快照，无法做"某年状态"筛选；列表 badge 仍显示当前状态（stageToGroup 派生）。
⑨ 域3 着色只有项目数：数据硬约束——TX 输送容量覆盖率仅 2.7%、里程 20.6%、电压是等级不可求和；MF 产能单位异质（GW/年、GWh/年、万吨/年）。下拉退化为单选项禁用态（保位置防布局跳动）。
⑩ 缺失值显示「—」：TX/MF 度量字段覆盖率低（TX 电压 60%、MF 产能 38%），无值项目规模位显示灰色「—」。

V1 评估

✓ 优点：视觉侵入最小，不新增任何布局层；控件紧凑，一眼可见三个域；实现最直接。
✗ 风险：域控件与筛选药丸同行同视觉层级，用户易把"域"误解为一个普通筛选条件（实际切域会重置类别/状态筛选、更换数据集与度量口径）；FilterBar 本已有 9 组控件，再塞一组，窄屏下 flex-wrap 换行后视觉密度高。
工作量：M（共通基建为主，控件本身 S）。
