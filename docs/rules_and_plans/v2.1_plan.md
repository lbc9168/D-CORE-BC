## 主题

v2.1 = **大幅重构提取/复核/去重的 agent 结构，系统性提升数据正确率**。核心驱动来自 problems#5「数据错误率比想象高、需要提升正确率的路径」。

## 子项目拆分与排序（已与用户确认）

| 子项目 | 内容 | 依赖 | 风险 | 状态 |
|---|---|---|---|---|
| **P0 · 金标准评测集 + 评测框架** | ~150 篇分层抽样、AI 草稿+人工改正的 ground truth；字段级准确率评测脚本（跑提取+缓存+报告） | 无 | 低 | 设计已定（spec 见 docs/superpowers/specs/） |
| **P1 · 提取多 agent 化 + 分类规则补全** | A.0 拆巨型 prompt 为多 agent（相关性/基本信息/金融/实体+参与/摘要自检）；A.1-A.5 分类规则（数据中心须RE、年发电量反推容量、设备主/次细分 + main_equipment.json 等） | **P0** | 高 | 待设计 |
| **P2 · 复核机制** | E.1 复核 agent（低置信字段二次核验）；E.2 未点名中企 `chinese_unnamed` 流 | P1 | 中 | 待设计 |
| **P3 · 去重分组 + 地点归一化**（从 S5 推迟） | 分组去 stage、地点/容量硬锚点、地点音译归一化、实体归一化副作用（S5 草稿见 sessions/S5_dedup_location.md Task2-5） | 可独立/P1 后 | 中-高 | 待设计 |
| **P4 · 外部信源换源**（可选/最后） | E.3 GDELT 换证券/官方公告源 | 信源可得性 | 中 | 待设计 |

**推荐执行顺序**：P0 → P1 → P2 →（P3 可与 P2 并行）→ P4（最后/可选）

## 关键排序逻辑：先造尺子（P0），再改东西

v2.1 核心卖点是"提升正确率"，但 A.0 把单 prompt 拆成多 agent 是双刃剑（可能更准、也可能引入新错且更贵）。**没有评测集就无法判断每次改动是进步还是退步**，只能凭感觉（change-suggestion A.6 同此意）。故 P0 最先做，作为 P1 及之后所有改动的度量基准。

## 各子项目流程

每个子项目独立走：brainstorm（设计）→ spec 落 `docs/superpowers/specs/` → writing-plans 出实施计划 `docs/rules_and_plans/sessions/` → 执行（建议各开干净会话）。P0 设计已完成。

## 与 v3 的边界

v2.1 不碰：多领域 domain、前后端分离、自动运行、访问统计（均 v3）。
