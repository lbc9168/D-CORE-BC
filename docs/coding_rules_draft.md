## Unit 1：Python 健壮性（错误处理与日志）

**规则 1：禁止沉默异常**

禁止使用 `except Exception: pass` 或裸 `except: pass`。
捕获异常时必须指定具体异常类型，并用 `logging.error()` 记录错误信息和上下文。
允许沉默的唯一情况是已知的、明确无害的边界（如 ALTER TABLE 列已存在），
且必须加注释说明原因。

**规则 3：统一使用 logging，禁止 print 输出运行信息**

所有运行时输出使用 `logging` 模块，禁止用 `print()` 输出操作信息。
日志必须写入文件，格式包含时间戳、模块名、级别和内容。
`print()` 仅允许出现在脚本的顶层入口用于人机交互提示。

## Unit 2：数据库原理（SQL + SQLite）

**规则 4：批量写入必须使用事务**

批量写入数据库时必须使用事务包裹，禁止在循环内逐条 `commit()`。
单次批量写入条数超过 50 条时，使用 `executemany()` 而非循环 `execute()`。

**规则 5：入口参数必须经过 Pydantic 验证**

所有对外暴露的函数入口参数必须用 Pydantic `BaseModel` 定义类型和约束。
日期字段需校验格式，数值字段需校验范围，路径字段需校验文件是否存在。
输入验证失败必须在入口处立即抛出，不得让非法参数进入业务逻辑。

## Unit 3：计算机网络基础（HTTP 与爬虫）

**规则 2：HTTP 响应必须检查状态码**

所有 HTTP 请求拿到响应后必须检查 `resp.status_code`，
不同状态码执行不同策略：404 直接跳过不重试，
429 等待至少 30 秒后重试，403 记录日志并终止当前任务，
5xx 按指数退避重试。禁止将未经状态码校验的响应直接传入解析逻辑。

## Unit 5：前端工程（React 与数据流）

**规则 6：外部数据必须在运行时验证结构**

TypeScript 的类型检查仅在编译阶段有效，`fetch` 返回的 JSON 数据在运行时不受类型保护。
所有从外部来源（JSON 文件、API 响应）加载的数据，必须在进入业务逻辑前用
`zod` 或等效库进行运行时结构验证。验证失败时立即抛出错误，
禁止让结构不符的数据静默流入组件渲染逻辑。

---

## Unit 4：并发编程（线程、锁、竞争条件）

**规则 7：多线程共享的可变变量必须加锁**

所有在多个线程中被读写的模块级全局变量，必须用 `threading.Lock()` 保护。
简单赋值（如 `_last_batch_id = batch_id`）不是线程安全的，
多线程环境下后写入的值会覆盖先写入的值，导致其他线程读到错误数据。
加锁范围：读取和写入都必须在 `with lock:` 块内完成。

---

## Unit 6：软件工程与系统设计

**规则 8：流水线各阶段必须在入口验证上一阶段的输出**

`pipeline/flow.py` 中每个阶段执行前，必须验证上一阶段的输出是否有效
（数据库文件存在、关键表非空、记录数量合理）。
验证失败时主动抛出带明确描述的异常，让 Flow 在可见位置中断，
禁止让空数据或不完整数据静默流入下一阶段。

**规则 9：API Key 和敏感凭据禁止出现在任何提交到 git 的文件中**

所有 API Key、数据库密码、服务凭据必须通过环境变量传入（本地用 `.env` 文件，
CI/CD 用 GitHub Secrets）。`.env` 文件必须在 `.gitignore` 中。
一旦凭据进入 git 历史，必须立即视为已泄露并轮换，删除记录无法消除风险。
