# S4.1 设计：stage-aware 时间模型（前端按年 + 4 大类 + 区间存在 + 按当年状态）

> 日期：2026-05-24
> 性质：**纯 s03 导出 + 前端**改造，**不碰 s02a 主库数据、不碰 DB 录入规则**（录入规则属 v2.1）。
> 工作区：worktree `worktree-v2`。完成后更新 `docs/status` + `docs/changes`。
> 上游：在 S4（事件级统计）基础上演进；**退役** S4 的 `stats_timeline_events` 聚合表，改用 per-project `stage_events`。

## 背景与问题

S4 把趋势图改成事件级，但暴露两个体验问题：
1. 顶部 "Project Stage" 筛选器（按项目**终态** `latest_stage`）与趋势图的"里程碑 tab"（按**事件** stage）语义打架，组合使用产生难以解释的"交集"。
2. 项目在可视化里仍以"终态年"塌缩，跨年项目的早期里程碑信息表达不清。

根因：用了两套不同的 stage 语义，且趋势图与筛选的联动是"国家+类别"粗粒度。

## 目标

- 前端可视化**不丢 stage**；同一份数据在**不同场景按需展示不同粒度**。
- 前端一律**按年**；月份只进下载 CSV。
- 把细 stage 归并为 **4 个可视化大类**，地图/趋势图/状态筛选统一用这 4 类。
- 跨年项目支持**区间存在性**（某年能不能看到它）与**按当年状态**（截至该年它处于哪一类）。
- 下载 CSV **按事件拆条**（一行一个 `project_event`），结构锁定，供 v2.1 录入对齐。

## 核心数据事实（已确认）

- `project_events`：PK `id` = `{canonical_id}-{NN}`（如 `IND-PV-0001-01`），含 `canonical_id`、`project_stage`、`publish_date`/`investment_date`、`capacity_mw`、`total_investment_usd`、`financing_model` 等。
- `chinese_entities`：按 `event_id` 关联到事件，含 `implementing_entity`、`subsidiary_name`、`involvement_type`、`is_central_soe`。
- `canonical_projects`：`id`、`project_name`/`_en`、`country`/`_iso`、`category`、`excluded` 等。
- 主库各 stage 计数（excluded=0）：签约 1753 / 中标 768 / 投入运营 715 / 拟开发 626 / 在建 499 / 开工 474 / 竣工 189 / Unknown 99 / 收购 61。

## A. 枚举层：4 大类映射（单一可信源）

在 `enums_mapping.json` 的 `project_stage` 每个条目加字段 `viz_group`，并新增一份 `viz_group` 字典（名称 zh/en、颜色、排序）。**禁止在 .py/.ts 硬编码**（遵 v2 约束）。

| viz_group | zh / en | 含细 stage |
|---|---|---|
| `pre_construction` | 前期 / Pre-construction | 中标、签约 |
| `under_construction` | 在建 / Under construction | 开工、在建 |
| `completed` | 完工 / Completed | 竣工、投入运营 |
| `acquired` | 收购 / Acquired | 收购 |
| `null`（隐藏） | — | 拟开发、Unknown |

- `bri_enums.py`：新增 `viz_group(stage) -> str|None`、`viz_groups() -> dict`（名称/颜色/排序）。
- `s04/src/utils/enums.ts`：暴露 `VIZ_GROUPS`（含 label/color/order）+ `stageToGroup(stage)`；构建期 `copy-enums.mjs` 已把 `enums_mapping.json` 拷为 `enums.json`，自动带上新字段。

## B. s03 导出层

### B1. `projects_flat` 新增（`flat_builder.py`）

- `stage_events`: `[{ group, year }, …]`，按 year 升序，**仅含映射到 4 大类的可见 stage**（拟开发/Unknown 不进）。精简，服务前端区间/状态/趋势。
- `first_event_year` / `last_event_year`：上面这些事件 year 的 min / max（区间边界）。无可见事件的项目 → 两者为 null（前端据此排除）。
- 保留现有 `latest_stage` / `latest_stage_en`（总体最新，给数据表用）、`display_order`（S3）。

### B2. 退役 `stats_timeline_events`

- `stats_builder.py`：删除 `stats_timeline_events` 表生成；`build_stats` 签名回到只读 `dst_db`（移除 S4 加的 `src_db` 参）。
- `json_exporter.py`：从导出表名列表移除 `stats_timeline_events`。
- `main.py`：调用改回 `build_stats(DST_DB)`。
- 前端不再加载 `stats_timeline_events.json`（趋势图改由 `stage_events` 客户端算）。
- 删除 S4 的 `s03_data_exporter/tests/test_stats_timeline_events.py`（其被测表已退役），由新的 `flat_builder.stage_events` / `events_exporter` 单测取代。
- `stats_country` / `stats_entity` / `stats_timeline` 保持不变。

### B3. 新增 `events_export.csv`（服务端生成，结构锁定）

新模块 `events_exporter.py`，join 三表，一行一个 `project_event`，写入 `data/output/` 并同步到 `s04/public/data/`。列：

| 列 | 来源 |
|---|---|
| `canonical_id` | project_events.canonical_id |
| `event_id` | project_events.id |
| `project_name_en` / `project_name_cn` | canonical_projects |
| `country_en` / `country_iso` / `province` | canonical_projects（+省份缓存） |
| `category_en` / `category_cn` | canonical_projects |
| `stage_cn` / `stage_en` / `stage_group_en` | project_events.project_stage → enums + viz_group |
| `year` / `month` | COALESCE(publish_date, investment_date) 截 4 位 / 7 位 |
| `capacity_mw` | project_events |
| `total_investment_usd` | project_events |
| `financing_model_en` | project_events → enums |
| `entities` | chinese_entities(event_id) 的 implementing_entity（"; " 拼接） |
| `is_central_soe` | chinese_entities(event_id) 任一为 1 → 1 |
| `verification_status` | project_events |

- 排除 `canonical_projects.excluded=1` 的项目；隐藏 stage（拟开发/Unknown）是否进 CSV：**进**（CSV 是全量明细，前端可视化才隐藏）。
- 前端"Download CSV"按钮改为指向该静态文件（`<a href>`），不再客户端拼装。

## C. 前端交互模型（s04）

### C1. 类型（`types/index.ts`）

- 新增 `type VizGroup = "pre_construction" | "under_construction" | "completed" | "acquired"`。
- 新增 `interface StageEvent { group: VizGroup; year: number }`。
- `Project` 增 `stage_events: StageEvent[]`、`first_event_year: number | null`、`last_event_year: number | null`。
- 移除对 `StatTimelineEvent` 的使用（类型可保留或删，趋势图不再用）。

### C2. 筛选状态（`FilterState` + `FilterBar`）

- 移除 `yearRange: [number,number]|null` 与 `stages: string[]`。
- 新增 `refYear: number | null`（单一参考年，默认 = 最新可用年）、`groups: VizGroup[]`（4 大类状态多选，空 = 全选）。
- `FilterBar`：年份控件改为**单柄滑块/下拉**（单年 Y）；"Project Stage" 多选改为 "Status"（4 项：前期/在建/完工/收购，渲染用 `VIZ_GROUPS`）。其余筛选不变。

### C3. 派生逻辑（`DataContext`）

- `statusAt(project, Y)`：`stage_events` 中 `year ≤ Y` 的最后一个事件的 `group`；若无（Y 早于首事件）→ 视为不在场。`Y` 为 null 时取总体最新事件的 group。
- `applyFilter`：
  - **区间存在**：`refYear` 非空时，仅保留 `first_event_year ≤ refYear ≤ last_event_year` 的项目；为空时保留有可见事件的项目。
  - **状态筛选**：`groups` 非空时，仅保留 `statusAt(p, refYear) ∈ groups`。
  - 其余（category/region/bri/ldc/soe/entity）不变。
- **基线策略调整**：现 `shouldExcludeByPolicy` 用 `event_year < 2022` 与 `latest_stage`；改为"有 ≥1 可见 stage_event"判定在场，年份下限交给 `refYear` 可选范围（`availableYears` 取自所有 `stage_events` 的 year，≥2022 维持）。category/entity/capacity 排除逻辑保留。
- 暴露 `refYear`、`statusAt` 帮助函数给列表/地图。

### C4. 趋势图（`TimelineChart` 重写）

- 输入 = 过了**除 `refYear` 和 `groups` 外**所有筛选的项目（图自带 4 tab 管阶段、自带全时间轴）。
- 4 个 tab：前期 / 在建 / 完工 / 收购（取自 `VIZ_GROUPS`，默认前期）。
- 选中 tab → 遍历项目 `stage_events`，取 `group == 选中 tab` 的事件，按 **year × category** 堆叠计数。全时间轴。
- 不再消费 `stats_timeline_events.json`。

### C5. 地图 / 列表

- 地图（国家 choropleth 按 count/capacity）：跟随 `filteredProjects`（已含区间存在 + 状态），无需改。
- `ProjectList`：状态徽章由 `latest_stage` 改为 `statusAt(p, refYear)` 的大类标签 + 颜色（用 `VIZ_GROUPS`）。需能拿到 `refYear`。

### C6. 数据表 / 详情 / 下载

- `TablePage`：屏幕表**不变**（一行一项目 = 总体最新 stage，默认 `display_order` 升序）。
- "Download CSV" → 指向静态 `events_export.csv`（C/B3）。`csvExport.ts` 客户端拼装逻辑废弃或保留备用。
- `ProjectDetail`：保留现有 timeline（`timeline_notes` 已到月），不变。

### C7. i18n

- 新增 4 个 `viz_group` 标签（实际由 `VIZ_GROUPS` 提供 en；i18n 仅需 "Status" 筛选标签、"Year" 单年标签、趋势图标题文案）。

## D. 语义示例（锁定）

项目 P：2023-01 签约（前期）、2024-05 开工（在建）、2025-10 竣工（完工）。`stage_events=[{pre,2023},{under,2024},{completed,2025}]`，`first=2023,last=2025`。

- `refYear=2023`：P 在场（2023∈[2023,2025]）；`statusAt=前期`。`状态=前期` 能看到，`状态=完工` 看不到。
- `refYear=2024`：在场；`statusAt=在建`。
- `refYear=2025`：在场；`statusAt=完工`。
- 趋势图（不受 refYear）：前期 tab 在 2023 计 1；在建 tab 在 2024 计 1；完工 tab 在 2025 计 1。
- `events_export.csv`：P 产出 3 行（含各自 event_id、stage、month）。
