# v2.1 P0.1 设计：多项目评测（multi-project alignment）

> 创建：2026-05-24
> 性质：设计文档（spec）。经 brainstorming 与用户逐节确认。实施计划另由 writing-plans 产出。
> 上游：P0 金标准评测框架（[spec](2026-05-24-v2.1-P0-eval-set-design.md) / [plan](../plans/2026-05-24-v2.1-P0-eval-set.md)）已落地（`eval/` 模块，分支 worktree-v2）。
> 本设计在 P0 基础上升级，使评测能覆盖「一篇文章多个项目」与「一个项目多家中企（各有角色）」。

## 目标（一句话）

让 s01b 提取评测从「每篇只比主项目」升级为「比全部项目」：度量提取器**枚举/分辨多个项目的能力**、以及每个项目内**多家中企及其各自角色**的抽取质量，使 P1 重构对这部分的进步/退步可量化。

## 动机

P0 简化为「每篇文章只比 status + 主项目」（`flat_prediction` 只取 `projects[0]`），多项目不对齐。人工标注时遇到真实案例：一篇新闻含两个**平行**项目（同容量、不同名，无主次），且涉及「外国供应商 → 中国 EPC」——P0 schema 无法承载第二个项目，也无法度量「是否分辨出两个项目」。本设计补上这一层（即 P0 计划里记的「多项目对齐留 P0.1」）。

## 范围

- 仍**只评 s01b 提取**（文章 → 提取字段），不评端到端管线、不评去重。
- 不改生产数据；评测读 `raw_news.db` 取原文 + 跑提取器，不写 `projects.db` / `bri_re_database.db`。
- 升级的是 `eval/` 内部结构 + gold/draft 格式；**因尚无任何真实 `gold_set.jsonl`，直接改 schema，无需迁移/兼容垫片**。

## 核心设计决策（brainstorming 确认）

1. **对齐键 = 项目名为主 + 属性助判**（类别/容量/地点）。
2. **枚举单独报 `project_set` P/R/F1**，不并入 `weighted_total`；字段准确率只在「对上的项目」上算（两个数互不污染）。
3. **`project_name` 只做对齐键，不单独评分**（抓没抓到由 project_set recall 体现，避免翻译/措辞差异被重复惩罚）。
4. **gold = 文章级 + 项目列表**（`status` 升到文章级）；**draft.csv = 一文多行、每行一个项目**，`status` 每行重复；零项目文章（no_chinese/irrelevant）= 单行只填 status。
5. **多家中企同项目 = 同一行**，`entities` 单元格写 `名字(角色); 名字(角色)`，**取消项目级 `involvement_type`，角色挂在每家实体上**。
6. **对齐算法 = 贪心**（非匈牙利）：项目规模小（一篇 1–5 个），贪心与最优近似等效且零新重依赖。
7. **`location` 记录但不硬评分**（与 P0 一致；地名归一化是 v2.1 S5 单独的事）。
8. **`NAME_THRESHOLD` 默认 80**，可配置。
9. **项目名相似度用 rapidfuzz**（与 s02a 去重口径一致），需加入 s01b venv 依赖。

## 数据模型（归一后的比较对象）

pred 与 gold 评测时都归一成同一嵌套结构：

```
article = {
  "status": "valid" | "no_chinese" | "irrelevant",     # 文章级
  "projects": [
    {
      "project_name": str,                              # 仅对齐键，不评分
      "category": str|None,                             # 枚举（cmp_enum）
      "project_stage": str|None,                        # 枚举
      "financing_model": str|None,                      # 枚举
      "capacity_mw": str|None,                          # 数值（cmp_numeric ±5%）
      "total_investment_usd": str|None,                 # 数值
      "location": str|None,                             # 记录不评分
      "entities": [ {"name": str, "involvement_type": str|None}, ... ]
    }, ...
  ]
}
```

- **pred** 来自 `extract_one` 原始 JSON → `flat_prediction`（取**全部** projects）。
- **gold** 来自 `gold_set.jsonl`（`csv_to_gold` 生成）。
- 两种存储（嵌套 gold vs 扁平 production DB）信息等价、互不影响打分——评测只比提取器**原始嵌套输出**，不碰扁平 DB。

### gold_set.jsonl（一行一篇文章）

```json
{"source_link":"http://x","article_id":"24366","status":"valid","projects":[
  {"project_name":"阿尔法光伏电站","category":"光伏","capacity_mw":"50","project_stage":"中标","financing_model":"Unknown","total_investment_usd":"-","location":"肯尼亚","entities":[{"name":"中国电建","involvement_type":"EPC总承包"}]},
  {"project_name":"贝塔光伏电站","category":"光伏","capacity_mw":"50","project_stage":"中标","financing_model":"Unknown","total_investment_usd":"-","location":"肯尼亚","entities":[{"name":"中国电建","involvement_type":"EPC总承包"}]}
]}
{"source_link":"http://y","status":"irrelevant","projects":[]}
```

### draft.csv（一文多行）

列：`source_link, article_id, _bucket, ai_status, status, ai_project_name, project_name, ai_category, category, ai_capacity_mw, capacity_mw, ai_project_stage, project_stage, ai_location, location, ai_total_investment_usd, total_investment_usd, ai_financing_model, financing_model, ai_entities, entities, notes`

- 同一篇文章多行（`source_link` 重复），`status` 每行填同值。
- `ai_entities`/`entities` 写 `名字(角色); 名字(角色)`。
- valid：N 个项目 N 行；no_chinese/irrelevant 与负样本：单行，项目列留空。
- utf-8-sig 编码（Excel 中文友好）。

## 对齐算法（贪心）

`align_projects(pred_projects, gold_projects, threshold=80) -> (matched, unmatched_pred, unmatched_gold)`：

1. 对每个 (pred_i, gold_j)，算 `sim = _name_sim(name_i, name_j)`（rapidfuzz `token_set_ratio`，名字先归一：去空白/标点、统一大小写）。
2. 候选 = 所有 `sim >= threshold` 的对。
3. 候选按 `sim` 降序；**平局**用属性接近度打破：同 `category` +1、`capacity_mw` 在 ±5% 内 +1（仅作排序权重）。
4. 顺序遍历候选，1:1 贪心占用（pred_i 与 gold_j 各只用一次），得 matched 对。
5. 剩下的 pred → `unmatched_pred`（误报）；剩下的 gold → `unmatched_gold`（漏报）。

## 评测指标与打分

### 单篇 `score_article(pred, gold) -> dict`

1. **status 闸门**：`cmp_status(pred.status, gold.status)`。status 错、或 gold.status ≠ "valid" → 停（不进项目打分），只返回 status 结果。
2. **贪心对齐**（valid 文章）→ matched / unmatched_pred / unmatched_gold。
3. **项目集**：本篇 `matched / pred_total / gold_total`（供上层 micro 汇总）。
4. **每个对上的项目**：
   - 5 个字段：enum{category, project_stage, financing_model} 用 `cmp_enum`；numeric{capacity_mw, total_investment_usd} 用 `cmp_numeric`。
   - 实体 `score_entities(pred_entities, gold_entities)`：
     - name 集合 P/R/F1（名字归一后按集合）。
     - role：对**两边同名**的企业，比 `involvement_type`（`cmp_enum`）→ 返回 `(role_correct, role_matched)`。
5. 未对上的项目**不进字段/实体分**，只影响 project_set。

### 跨文章汇总（`run_eval`）

进入打分的文章 = valid 且 status 对（记 `n_scored_articles`）。

| 指标 | 汇总 |
|---|---|
| `status_accuracy` | status 对文章数 / (n_gold − n_skipped − n_failed) |
| `project_set` P/R | **micro**：Σmatched/Σpred、Σmatched/Σgold，再算 F1 |
| `fields[f].accuracy` | **micro**：Σ对上项目该字段判对 / Σ总数 |
| `entity.name_f1_mean` | 所有对上项目的 name F1 **平均**（macro） |
| `entity.role_accuracy` | **micro**：Σrole_correct / Σrole_matched |
| `weighted_total` | status / 字段均值 / name_f1_mean / role_accuracy **四分量**加权，默认等权（各 0.25），缺数据丢弃再归一；`WEIGHTS` 可调。`project_set` **不并入** |

### 算例（实施测试据此断言）

gold 2 个平行项目（同名族、容量 50、中国电建 EPC）；pred：阿尔法对、贝塔(类别错综合能源/容量48/角色错设备供应商)、+ 多吐"配套储能"。
→ 对齐 matched=2、unmatched_pred={储能}。project_set：P 2/3=0.667、R 2/2=1.0、F1 0.80。
→ 字段 micro：category 1/2=0.5、stage 1.0、financing 1.0、capacity 1.0(48 在 ±5%)、investment 1.0 → 均值 0.90。
→ 实体：name_f1_mean 1.0；role_accuracy 1/2=0.5。
→ status 1.0 → weighted_total=(1.0+0.90+1.0+0.5)/4=**0.85**。

## 数据流

```
raw_news.db ──(url)──► run_eval ──► extract_one ──► 原始嵌套 JSON ──► flat_prediction(全部项目)
                          │                                              │
gold_set.jsonl ──gold_loader──► 文章对象 ──► score_article(闸门+贪心对齐+逐对打分) ──► reports/<ts>.json
                                                                          ▲
build_draft → draft.csv → (人工标注) → csv_to_gold ──────────────────────┘
```

## 错误处理（遵 CLAUDE.md 规则 1/2）

- 单篇 extract 失败 → 记 `n_failed` + `logging.error`（含 source_link），不中断。
- 取不到原文 → `n_skipped` + warning。
- gold/CSV 非法（status 不合法、entities 角色括号不闭合等）→ 带行号/文章定位**立即抛错**（外部数据边界）。
- 无静默 except；缓存命中优先（缓存 key 仍 `sha1(url + extractor_version)`，extractor_version 随 prompt 变）。

## 测试策略（TDD）

- `test_predict.py`：多项目 + per-entity 角色摊平。
- `test_csv_to_gold.py`：多行聚合、`名字(角色)` 解析、status 每行重复、零项目文章、correct-only/空标记。
- `test_run_eval_e2e.py`：多项目 mock 文章（注入 extract_fn，不调 Gemini）→ 断言 project_set/fields/entity 各数 + 报告落盘。

## 开放项（实施时定，非阻塞）

- `_name_sim` 具体用 `token_set_ratio` 还是 `WRatio`——实施时按真实项目名试调，默认 `token_set_ratio`。
- 属性平局打破的加权细则（同 category / 容量 ±5%）——默认如上，可在实施时微调。
- 是否给 `project_set` 也并入 weighted_total——P0.1 默认不并入；若后续认为需要，仅改 WEIGHTS。

## 单一可信源 / 规则遵循

- 枚举归一复用 `bri_enums`，数值解析复用 `bri_parse`（±5%）。
- 项目名相似度复用 rapidfuzz（与去重口径一致）。
- `.env` 提供 API key，不入 git；draft/gold/cache/reports 已 gitignore。
