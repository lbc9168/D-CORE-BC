# s02e：结构化证据核验与开发样本复验

## 目的与当前状态

在已验收的参考链接产品形式内，修复开发样本的错误放行。本文记录问题依据、设计取舍、执行步骤和验收结果，不另行调用 Superpowers 工作流。

用户于2026-09-06通过单项目产品验收，并授权扩展30事件校准；本轮进一步授权按诊断继续改进并将过程记录在本目录。全量预算和生产发布仍未授权。

当前冻结样本为主表20、TX5、MF5，共29项目30事件；开发20事件、留出10事件。36候选、26可读。结构化开发复验后，DeepSeek安全接受8条，其中3条事件参考；Gemini原生Schema复测安全接受4条，但有11条抽取/证据跨度失败。DeepSeek已按冻结规则完成10事件留出（8个可读页面），接受0条，来源身份规则覆盖不足，仍不达到全量门槛。独立标签为代理复核草稿，尚非人工确认金标准。

## 问题依据与设计取舍

| 观察 | 当前缺口 | 本轮处理 |
|---|---|---|
| 引用“2023年”即可被判投运，引用“中标”被判开工 | 布尔结论与引文存在检查不能保证语义支持 | 模型提供观察到的动作/状态/时间及证据位置；程序比较，不能由模型自行决定通过 |
| 老挝子变电站3月并网与整体线路4月投产被合并 | 设施范围和实际日期未分别绑定 | 独立目标核验卡保留设施、日期精度与证据；不匹配只作项目参考 |
| 新浪托管页被当作新浪采编 | 原始来源身份没有独立校验 | 少量经核对的发布机构表，平台与原始来源分别记录；未知身份待确认 |
| 原新闻标题“中标”、正文“签约”；容量存在历史版本 | 目标事实不一定自洽 | 原库只读，争议放入独立目标卡；不修改冻结标签来迎合模型结果 |
| 新提示词把并网和运营绝对分开 | 与现有上游分类规则不一致 | 复用s01b阶段映射：并网发电/投产/商业运行均可映射投入运营，同时保留具体动作 |
| 可读页22/26未提取独立发布日期，一些正文有导航和重复 | 页面结构丢失，模型自行补时间 | 对缓存正文分段编号、去除完全重复段落，保留独立时间证据；不凭URL日期认定事件日期 |

主要选择：保留项目识别中的模型判断，但取消其对发布者信任和最终事件归属的单方决定权。可机械检查的动作、日期、设施词和容量以可定位证据为输入；仍无法确定的语义关系保留待确认。项目匹配但阶段不足可降为项目参考；身份/关键容量冲突不能降级绕过。

为隔离变量，本轮继续使用同一冻结网页正文，不重新搜索、不改生产事实、不重抓全部页面。开发集目标卡只依据目标原新闻和数据库生成，不参考模型输出；作为本地校准输入，不冒充已完成全量自动目标标准化。未知或矛盾目标明确标记，后续不能据此宣称生产就绪。

## 执行步骤与验收合同

1. **冻结本轮输入。** 保留旧语料、标签、规则及判定；新增开发集目标卡与小型来源机构表，记录作者、依据和指纹。保留10个留出事件不参与规则修订。
2. **实现结构化输出与程序判定。** 候选正文使用段落编号；结构化输出绑定项目识别、容量和事件观察。程序检查引文、实际/计划、阶段映射、事件日期、设施范围和来源身份；输出具体拒绝/降级原因。保留旧单项目入口和历史结果。
3. **定向验证。** 用真实错误形态及正确例子验证中标/开工、计划/实际、仅年份、子设施/整体、转载来源、容量冲突；验证并网到投入运营的既有映射。确认预算预留、续跑和只读不变性。
4. **开发样本复测。** 相同目标卡和18个可读候选分别调用Gemini与DeepSeek，默认每模型最多18次，无新搜索。记录请求参数、用量、结果和规则快照。未知来源可由程序直接隐藏，仍保留模型抽取用于诊断。
5. **交付并判断是否进入留出。** 报告改进前后安全接受、错误放行、项目/事件覆盖、未解决口径争议和费用。明确区分代码错误、目标不确定、抽取失败、模型语义错误。开发门槛未过则不调用留出；开发通过也不能把代理草稿标签称为正式人工验收。

停止标准：本轮结构化路径、预算/来源不变性及定向测试通过；开发比较有完整记录；剩余错误与下一步边界明确。只在新改动或未解决问题影响结果时增加验证，不以调参循环替代真实验收。
