# s02e：从Google搜索到合格参考的下一阶段计划

## 决策目的

验证Gemini内置Google搜索能否提高实际可用参考的覆盖，同时保持项目、事件和来源身份准确。本文为下一步方案，不代表本轮已启动新批量调用，也不构成全量预算或发布授权。

制定计划时的基线：旧结构化校验可以拦住错误阶段，但发布机构规则覆盖不足；Google搜索3事件试验已返回6条旧冻结语料之外的URL，其中包含英文和转载，当时尚未抓取这些目标的完整正文。下方执行记录更新实际结果。

## 建议流程

目标项目/事件 → 检查已有参考 → 必要时Gemini Google补搜 → 解析真实URL、去重和抓取正文 → 来源身份核实 → DeepSeek事实抽取与程序判定 → 可复核的项目/事件参考。

Gemini先作为候选发现工具；DeepSeek继续承担当前较稳定的正文抽取。该分工依据已有实测，是待验证的开发选择，不是最终生产模型结论。Serper保留现有能力，只有Google搜索实际找不到或不可用时做有限补充，暂不安排所有模型×所有搜索方式的全组合比较。

## 第一步：把刚找到的候选走完

- 复用`data/google-grounding-smoke-v1/resolved-links.json`中的6条新URL，不重复调用Google搜索；英文页按现有中文参考要求排除，其余抓取正文。
- 对未解析的阳光电源Google引用单独检查访问问题；只在明确可重试时做有记录的有限重试，不关闭TLS或改写旧成功记录。
- 按实际发布者区分官网首发、媒体采编、转载、平台作者。新浪/腾讯/网易只是托管平台时，不直接继承平台媒体身份；可找到合格原始来源时保留转载链。
- 分别检查项目身份、容量口径、动作、发生日期与设施范围；项目明确而阶段不足可保留项目参考，不能自动提升为事件证据。
- 产出逐条表：真实URL、新旧标记、是否可读、实际发布者、关键原文、实际动作/日期、最终分类和未通过原因。

完成标准：明确回答“6个新URL中，实际增加了多少条合格中文项目参考、多少条事件参考”，而不是只报告搜索返回多少链接。

## 第二步：修正来源识别并完成5事件开发闭环

首要修正是把“站点未登记”和“来源不可信”分开。对首次出现的发布者，核对官网/关于我们/转载署名及集团内部组织关系，保存带依据的机构记录；确认机构身份后，同机构的不同文章仍须逐条核对项目和事件。证据不足继续待确认，不按这几个项目的答案硬编码放行。

从已看过的样本中选5个已知问题形态作开发，不声称独立测试：已有正确链接、旧链接错配、只有项目资料、转载署名不明、没有外链。先固定名单、目标解释及验收依据，再跑完整流程。

建议该5事件开发批次上限：每事件最多2次Google grounded请求、最多4条新增正文候选；总计最多10次Google请求、20条新增候选校验。已有正文和判断优先复用，失败及不明请求照样计入账本，不自动扩大上限。阶段一的现有候选验证单独记账。实际执行前做零调用预览并记录模型、prompt、数据披露范围及费用口径；本计划不按账号免费额度假定零成本。

有限搜索后允许没有合格参考，不用强制凑链接。明确区分：没有找到、网页打不开、找到了但不是同项目、阶段不符、来源身份不足、目标原始事实有争议。

完成标准：5个事件都有完整、可解释的终态；有真实正确参考被保留；无错误项目或阶段放行；主要失败原因可归因。交付一张结果表及至少一个真实详情页预览，避免仅用后台测试替代产品验收。

## 第三步：冻结规则，用10个新事件验收

- 从此前30事件之外选择10个新事件，主表/TX/MF均有覆盖，并按项目、原新闻、候选URL隔离；在执行前保留多个独立确认有合格外部报道的正例。
- 先确定目标卡和独立复核依据，再冻结搜索策略、机构核实程序、模型提示词与判定规则。标签及已知参考答案不发给搜索或校验模型。
- 本次旧留出已用于诊断，不再次称为未见样本；新验收发现问题后保留原始结果，不改标签/规则再在同一批上宣称独立通过。
- 同时报两类结果：找源覆盖（多少事件获得项目/事件参考）与核验质量（正确保留、错误放行、误挡可用链接）。记录实际请求、搜索查询、token和人工复核量。

建议门槛：错误项目放行=0、错误阶段放行=0；对本轮候选池中独立复核确认可用的链接，正确保留比例至少80%，且存在正确事件参考。该80%是待采用的验收目标，不是实测结果，也不是全网检索召回率。搜不到的事件单列，不能把全部隐藏当作通过。样本很小，结果仅用于决定下一阶段，不外推全库精度。

边界或口径争议集中放入一张人审表，由用户最终确认；代理复核草稿继续明确标记，不能改称人工金标准。

## 再下一步：通过后才接生产数据

1. 根据实测覆盖、每条合格参考的成本和人工复核量，确定默认搜索/校验分工以及全量范围、预算。
2. 实现独立验证库：按项目＋事件＋URL保存状态、原文证据、实际发布者/转载链、版本、核验时间与有效期；不改项目核心事实。
3. 接入s03的`external_references`导出，复用已验收详情组件；验证一条完整导出到页面路径、旧格式兼容与源库不变性。
4. 先处理一个有硬上限的小批次，核对公开结果后，再安排存量和增量维护。正式发布按实际验收和授权执行。

上述生产步骤依赖新样本验收通过。本阶段先把“找到候选”变为“产出正确可用参考”，不提前投入全量调度或新架构。
