# Golden Standard 分层归一化原型计划

> 日期：2026-08-09  
> 范围：阶段 3 十篇 Pilot 的实体与地点复核；不进入阶段 4，不修改生产数据库。

## 1. 目标

在现有冲突优先复核页中明确区分“原文抽取事实”和“确定性归一化结果”，使同一条事实可以分别评价 S01B 抽取质量与 S02B 归一化质量，不再要求用户在原文公司名和母公司之间二选一。

## 2. 字段分层

每个 Gold 项目新增两项规则层字段，并保留现有事实层字段：

| 层 | 字段 | 含义 | 候选来源 |
|---|---|---|---|
| S01B 事实层 | `entities` | 原文出现的中国实体名称与参与角色 | Pipeline、Terra、Sol、数据库事件的原始/子公司显示值 |
| S02B 规则层 | `normalized_entities` | 标准实体、母公司及继承的参与角色 | 当前 Pipeline/主库中的确定性归一化结果 |
| S01B 事实层 | `location` | 原文抽取的地点 | Pipeline、Terra、Sol、主库 `location` |
| S02B-2 规则层 | `normalized_location` | 标准地点名称 | 主库 `location_norm` 优先，否则按现有 Pipeline 语义回退 `location`；两者均空才是不提及 |

S02A 继续表示项目 duplicate merger、事件归属与 canonical project 对齐，不把它称为地点归一化。

## 3. 交互

- 字段标题显式显示 `S01B 事实层` 或 `S02B 规则层`。
- Terra/Sol 只出现在事实层，不因缺少母公司而形成伪冲突。
- 规则层候选可以单独采用、编辑、设为未知/不适用/待复核并保存草稿。
- 事实层 `present` 值在确认时仍要求原文逐字证据。
- 规则层不要求母公司或标准地名必须逐字出现在新闻；确认时要求人工处理状态，但允许以登记册/规则说明代替原文证据。
- 已有草稿在加载时只补充缺失的新字段，不覆盖任何人工值；确认后的工作副本仍须先“重新打开复核”才能保存。

## 4. 最小实现文件

- `single_article.py`：分别投影原始实体、标准实体/母公司与原始/标准地点。
- `app.py`：增加两个规则层字段、候选映射和旧草稿兼容补全。
- `draft_store.py`：将新字段纳入完整确认，同时区分原文证据字段与规则派生字段。
- `review.js` / `style.css`：显示字段层级、规则层说明和候选来源。
- `test_single_article_flow.py`：覆盖真实文章 1533 的三一硅能→三一集团，以及规则层不要求母公司出现在原文。

## 5. 验收标准

1. 打开 `/review/1533`，`S01B 原文实体与角色` 中 Terra/Sol 显示“三一硅能”。
2. 同一项目的 `S02B 标准实体与母公司` 显示“三一硅能 → 三一集团有限公司”。
3. 两层字段可分别采用和编辑；草稿刷新后恢复。
4. 标准母公司不在新闻正文时，草稿仍可保存，完整确认不会错误要求母公司逐字证据。
5. 原文事实字段仍保持严格证据门控。
6. 三份上游 SQLite 保持只读且不发生修改。

## 6. 明确不做

- 不调用新的 Provider/Reviewer，不重写既有候选 artifact。
- 不修改 S01B、S02A、S02B 生产逻辑、目录、环境变量或数据库 schema。
- 不实现 S02A duplicate decision 的完整人工标注界面，不发布 Gold，不做 200–300 篇扩展。
