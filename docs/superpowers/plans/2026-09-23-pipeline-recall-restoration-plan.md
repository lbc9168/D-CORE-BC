## 4. 目标流程与职责

`S01A采集 → S1候选初筛 → S2项目/事件与基本事实 → S34企业参与及金融信息 → Python结构与数值检查 → S5摘要 → S02A项目/事件/关系去重 → S02B辅助标准化 → S03隔离导出`

保留S34合并模式。同步维护S3/S4独立模式，防止关闭合并开关后恢复旧式拦截。S5继续只摘要，不重新裁定身份、角色、阶段、容量。

### 4.1 S1：保持候选召回，不提前作最终身份结论

- 明确不在业务范围的排除；有合理项目及中企线索则继续。
- 不熟悉简称、品牌、英文名称，不能单凭此判无中企。
- 名录命中仅作辅助线索，不因“乌兹别克斯坦国家电网”含中国国网别名而强行赋予中企身份。
- 将给S2的前提改为“候选文章，尚需逐项目判断”，不能声称已确认含中企。
- 统一S1/S2的三类记录口径：可识别物理项目；有实质供货行为的设备订单；无具体工程的框架合作。设备订单和合作可保留在现有非项目记录通道，不伪装电站；国家目标、纯评论等仍按既有范围排除。

### 4.2 S2：先辨认物理项目，再提取字段

- 区分本次报道的事件、历史背景和未来组合；只有独立、明确的新事件才增加本篇事件记录。
- 不同场址/不同工程保持分开；同项目多家参与企业不拆项目；发电项目内部升压站不另造TX。
- 一笔订单和若干物理电站是不同对象；不得由订单总量反推多个电站，亦不得强并已明确的异地电站。
- 保留简短原文项目标识、文章中明确的别名及必要上下文，并传入S34。展示名称不再承担硬身份校验。文章内编号只用于本轮对应，不替代持久canonical ID。
- 不要求锚点与规范化项目名逐字匹配；允许“戈布斯坦地区”和“戈布斯坦光伏项目”在上下文中对应。仅容量相同、国家相同不能单独证明同项目。
- 容量、阶段、业主分别处理：首次点火不能自动写投运；单机与总量、MW与MWh、发电与储能、单站与组合明确区分。
- 容量/业主/日期缺失不否定项目。旧Prompt中多处重复、例外冲突的规则统一到同一处，减少针对单篇新闻不断加规则。

### 4.3 S34/S4：以语义判断参与，取消句式和名录硬门槛

模型负责判断“谁参与哪个项目、具体做什么”。允许跨句、代词、列表、标题与正文联合理解。依据可以是多个分别定位的片段；不要求拼成连续引文，不要求每个片段同时出现企业、项目、动作，也不要求固定动词。

Python不再用下列任一条件单独否定参与或整项目：

- 引文不连续或存在无害格式差异；
- 项目锚点和展示名称不相同；
- 未找到固定动作正则；
- 企业未命中登记册、无entity_id、无明确母子关系；
- 新闻没有逐字写“中国企业”；
- 角色未知或辅助字段为空。

保留原文企业名。名录可补充规范名和已有ID；未命中时，模型有合理中企判断且参与成立，可按原文名建立关系，entity_id等未知项留空，不自动新增到受控名录，不假装已人工核实。

身份判断依据要区分“原文”“现有名录”“模型背景知识”“仍不确定”。模型可识别常见企业、品牌、简称，不需要逐个联网查证才能放行。不要把“模型说是中企”转换成已核实法人身份；也不要用统一的高置信度分数阈值代替旧名录门槛。

真实歧义才进入pending：例如名称确实可能是同名外国公司且上下文无法区分；明确外企与模型中企结论冲突；无法确定企业参与的是哪个项目。已核实外企记录提供实质反证，但普通别名未命中不是反证。

“企业参与成立”和“具体角色成立”分开。使用品牌设备可以保留参与，具体供货角色按全文语义判断，不要求原文出现“合同”；若只有品牌使用且合同职责不明则Unknown。不得把设备供应推成EPC/业主，把合作开发自动推成持股。

### 4.4 金融与可选字段：问题局部处理

- 分开总投资、工程合同额、债务融资额，不把一个金额复制给多个字段或多个项目。
- 组合金额在未分配时只保留组合说明/原始事实，单项目数值留空。
- 原币及原金额保留；美元转换需记录汇率依据。现有输入没有可复现转换依据时，保留原币金额、美元数值留空，不新增联网汇率服务作为运行依赖。
- 融资模式与金额分开：不知道融资工具不影响正确投资额，也不影响企业参与。
- 电压115/22kV保留完整规格；主电压的既有字段按明确口径处理，不能误取22kV。
- 容量引文/格式错误不自动代表项目身份错误。若不能修复，清空对应发布数值并保留原始候选和字段警告；不能残留在摘要、名称或回填环节中冒充已接受数值。
- S02B补回一个字段时，应同时更新该字段的有效状态；旧错误保留审计，不继续充当当前阻塞。不得仅清掉needs_review来掩盖问题。

### 4.5 发布与下游契约

| 情况 | 处理 |
|---|---|
| 中企参与可合理确认，名录未命中或法人未细分 | eligible；保留原文企业名及判断来源；规范身份待完善，不阻止S02A/S03 |
| 参与明确，角色不明确 | eligible；角色Unknown |
| 项目明确，容量/金额/业主不明确 | eligible；相关字段空值及警告 |
| 某一参与方有歧义，另一中企关系明确 | 已接受关系流转；有歧义关系单独pending |
| 项目边界或是否有中企参与确实无法判断 | pending_review；保留可解释的业务理由 |
| 明确越界或明确无中企参与 | excluded/既有非项目通道，按业务语义处理 |
| 请求超时、JSON结构损坏、写入失败 | 技术失败，可续跑；不得冒充业务排除 |

新接受语义不可只在S34生效。检查writer、S02A、S02B、S03及前端现有过滤，确保身份标准化待办/字段警告不会又变成整项目excluded。

保留原有ID和跨事件关系：未匹配企业按原文名称和项目事件上下文保持稳定，不启用全库模糊合并；将来匹配到法人时须有可追踪协调。新增pending来源不得连带排除已有有效canonical。

## 6. S34 核心指令草案

下列文本供执行者融入现有Prompt。不是完整API输出Schema；不得只替换这段而不改对应后处理。

> 你负责从新闻中识别目标项目的企业参与和金融事实。文章已通过候选初筛，但每个项目是否有中企参与仍需你判断。
>
> 根据全文语义、标题、上下文、列表及明确指代判断谁参与目标项目。不要要求企业、项目和动作出现在同一句；不要把没有固定动词、没有连续引文、项目简称不同视为未参与。可以给出多个原文片段，并简述它们如何支持判断。片段尽量保留原文；不能定位的片段应标明，不能编造证据。
>
> 保留企业原文名称。可以结合常见企业知识及提供的名录线索识别中方企业、品牌和简称。名录未命中、未提供法人全称、新闻未注明国籍，不代表无中企参与。中企判断与规范法人匹配分别记录；真正的同名歧义或相互矛盾信息才标为不确定，不凭名称相似强行指定法人或母公司。
>
> 先判断是否参与，再判断角色。参与明确而角色不明时保留该企业，角色Unknown。全文明确提供设备、供货或承担设备职责即可判断供应商，无须出现特定合同句式；仅使用某品牌设备而合同关系不明时仍保留参与。不得把供应商推成EPC、把承建一概推成全EPC、把合作一概推成股权、把参与推成业主。
>
> 不借用其他项目或背景企业的参与，不把否定语句当肯定。多个项目共用的金额、容量或企业关系，仅在原文明确共同适用时对应；组合总额未拆分则保留组合说明，不给每个项目重复赋值。
>
> 总投资、合同额、债务融资额和融资工具分别填写；未披露或不能确定归属的字段留空。原币金额保留，无可复现汇率依据不编造美元数值。金融字段未知不否定项目和企业参与。
>
> 返回规定JSON结构、简短判断依据和必要的原文片段。不以“资料不完全”作为整项目不录入的默认理由，也不为了提高通过率把真实歧义写成肯定。
